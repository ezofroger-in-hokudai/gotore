# GO TORE デザインルール v1.1（#54・#56）

2026-09-08のユーザー合意は「最終的なスマホアプリ化を前提にする」「文字を増やしすぎない」「やる気につながる赤を使う」。追加要望は「通常操作でスクロールさせない」「大きすぎる文字や角丸の箱を避け、硬派にする」。以下を画面改善の基準とし、v1の大きな文字・角丸カードの基準を更新する。具体的な色値・寸法はこの方針を実装するための基準値で、代表画面の比較をもとに改訂する。

[画面見本](design-preview.html) / [画像](images/design-templates.png) / [短い文言のルール](ui-copy.md)

## 基本

- スマートフォンの縦画面・片手操作を基準にする。主操作を見つけやすく、指で押しやすくする。
- 白・薄いグレーを背景に、赤を主操作と選択状態に使う。抑えた文字サイズ、数値の太さ、明確な操作で実績を伝える。
- 通常操作は1画面で完結させる。種目・セット・一覧は表示量を区切って切り替え、詳細や補助操作は別の表示にする。
- 直線・細い区切り線を基本とし、角丸カード・カプセル型の装飾・影を使わない。文字を極端に縮めて情報を詰め込まない。
- 文言は「記録」「保存」「メモ」など短くする。説明は初回ガイドにまとめる。単位・共有範囲・取り消せない操作の確認は短く残す。
- 色の用途、文字の役割、余白の段階、部品の状態を共通化する。ネイティブ版ではOSの戻る操作・文字拡大・日付入力等に合わせる。

## 色

| 用途 | 初版値 | 使う場所 |
| --- | --- | --- |
| 主色 | `#D32F2F` | 保存・記録などの主操作、選択状態 |
| 押下 | `#B71C1C` | 主操作を押している状態 |
| 薄い赤 | `#FDECEC` | 選択中の背景。赤文字と組み合わせる |
| 背景 | `#FAFAFA` | 画面全体 |
| 面 | `#FFFFFF` | 入力・メニュー |
| 本文 | `#1F1F1F` | 見出し・数値・通常の文字 |
| 補助文字 | `#666666` | 日付・単位・補足 |
| 区切り | `#E5E7EB` | 装飾的な区切り線 |
| 入力枠 | `#767676` | 入力欄の識別が必要な枠 |

赤い塗りの主ボタンは画面の主操作に絞る。削除は通常画面では補助操作とし、確認画面で対象と「削除」を明示する。色だけで選択・成功・失敗を区別せず、短い文字・形・アイコンも使う。

白文字と主色は約4.98:1、補助文字と白は約5.74:1。通常の文字は4.5:1以上を確認する。薄い区切り線は操作部品を識別する唯一の手掛かりにしない。

## 文字・余白・操作領域

| 項目 | Webの基準 |
| --- | --- |
| 本文・ボタン | 14px相当（0.875rem） |
| 入力文字 | 16px相当（1rem） |
| 補助・日付・項目名 | 12 / 14px相当 |
| ナビの短いラベル | 12px相当以上 |
| 見出し | 16 / 18px相当、太字 |
| 主な実績の数値 | 20 / 24px相当、太字。単位も表示 |
| 行間 | 本文1.5、見出し・数値1.2〜1.4 |
| 余白 | 4 / 8 / 12 / 16px相当。画面左右12〜16、節の間8〜12が基本 |
| 角丸・装飾 | 原則0。OS標準部品は尊重。大きな角丸・影・装飾カードなし |
| タップ領域 | 幅・高さ48 CSS px以上。見えるアイコンは小さくてもよい |

Webの文字はremを使い、ネイティブ版はOSの文字拡大に対応したスタイルへ割り当てる。iOSのpt、Androidのdp/sp、WebのCSS pxは同じ物理寸法として扱わない。iOSは44×44pt以上、Androidは48×48dp以上の操作領域を確保する。

OS標準の日本語サンセリフを基本にする。太字は見出し・主な数値・主操作に絞り、長い種目名や拡大文字は折り返す。ボタンやタブを省略して意味を失わせない。

## 共通部品・状態

| 部品 | ルール |
| --- | --- |
| 主ボタン | 赤地＋白文字。主操作は原則1つ。送信中は二重操作を防ぐ |
| 補助ボタン | 白地＋枠、または短い文字。主操作より控えめにする |
| 入力 | 短いラベルを欄の外に置き、単位を明示。数値入力に適したキーボード |
| 記録の行 | 日付・種目・セット数など必要な要約を細い区切り線で整理。詳細・編集等は別の表示へ |
| ナビゲーション | 下部に短いラベル。アイコンは識別を助ける場合だけ使う。選択状態は赤と下線・太さで示す |
| 通知・エラー | 状態と次の操作を短く示す。成功通知を重複させず、失敗時は入力を保持 |
| 読み込み | 初回・再取得・空・失敗を区別。保持した古い記録の再確認中は「更新中…」 |

全操作に押下・無効・フォーカス状態と読み上げ名を用意する。アイコンのみの補助操作にも読み上げ名を付ける。アニメーションは短く控えめにし、動きを減らす設定を尊重する。

## 画面テンプレート

| 型 | 上からの配置 |
| --- | --- |
| 一覧 | 短い見出し → 日付・共有先等の絞り込み → 要約／一覧 → 主操作 → 下部ナビ |
| 入力 | 戻る＋見出し → 日付・入力中の種目 → 推定1RM・最高重量 → 種目メモ → セット入力 → 保存 |
| 設定 | 見出し → 項目を用途ごとにまとめた行 → 詳細・変更画面 |

通常の記録は1種目を表示し、種目名・自己ベスト・短いメモ・セット入力・保存が1画面で見える構成にする。複数種目を縦に積まず、前／次や種目選択で切り替える。セットは画面に収まる行数に区切り、表示中の範囲と全件数を示す。一覧も日付選択・ページ切り替えを使う。ページ切り替えで下書きを失わない。

通常の文字サイズ・キーボードなしで、390px幅・有効表示領域720px高を基準に縦スクロール不要を確認する。長いメモは専用編集表示へ、小さい表示領域ではセットの表示行数を減らす。文字拡大やキーボード表示時は必要な範囲のスクロールを許容し、内容を切り捨てたりフォーカスや保存を隠したりしない。下部の固定操作は本文・キーボード・安全領域と重ねない。

画面見本は構成と見た目の参照用で、ボタンは動作しない。集約単位や共有ルールなどの業務仕様は既存docsと各Issueに従う。

## 記録入力の必須情報（#56）

2026-09-08の追加要望により、入力中に次を確認できることを最低条件とする。

- 入力中の種目名を明示し、その種目の自己ベストとして「推定1RM」「最高重量」を単位kg付きで並べる。推定値と実際に扱った重量を混同させない。
- 両方とも本人の保存済み履歴が対象。それぞれの最高値を示し、同じセットから選ぶ必要はない。未保存の入力を過去の自己ベストに混ぜない。
- 種目に残したメモ（例「肩に気をつける」）を表示する。ラベルは「メモ」とし、同じ欄で読んだり書き足したりできる。初期表示で折り畳まず、次回その種目を選んだときも参照できる形にする。
- 種目を切り替えたら、その種目に対応する自己ベスト・メモを表示する。前の種目の値を混ぜず、未保存メモを無断で破棄しない。
- メモは本人用として扱い、既存の[記録単位メモ](private-workout-memo.md)とは保存対象を区別する。種目メモをグループへ自動公開しない。
- 履歴なし・読み込み中・取得失敗を区別する。未取得を0kgとして表示せず、失敗時もセットとメモの入力を保持する。

[入力画面の拡大見本](images/record-context-mobile.png)。見本の数値とメモは架空の表示例で、実績の集計・計算・保存は実装していない。

今回の合意は表示項目と配置。推定1RMの計算式・対象回数・自重種目の扱い・種目の同定は#17、種目メモの保存タイミング・文字数・編集競合・種目削除時の扱いは#22で実装前に定義する。種目をグループ固有にするかの判断は引き続き保留する。

## 適用・確認

文書化は#54・#56（imtkgtr）。画面への適用は#8、ホームの表示整理は#30（どちらもIXYZONE）。現行CSSは未移行であり、この文書だけではアプリの表示は変わらない。

1. 共通の色・文字・余白を変数と部品にし、まず一覧・入力の代表画面で比較する。
2. 通常390×720pxの有効領域で縦スクロール不要を確認する。320〜430px幅・文字200%・長い日本語・キーボード表示も確認し、必要時の縦スクロールを許容して欠け・横スクロール・操作の重なりを防ぐ。
3. 読み込み・空・エラー・共有範囲・削除確認も比較画像へ含める。
4. #8のユーザー確認後、各画面へ展開し、実装差分に応じてmake check・共有E2E・実機確認を行う。

画面実装の進捗は各Issueで追跡する。モバイルの技術選定は[開発方針](development-policy.md)に従って別途扱う。
