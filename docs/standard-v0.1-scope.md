# スタンダード版 v0.1 — グループ・記録・共有

状態: ローカル実装・自動検証完了。ユーザー指定の初版の完成ラインは「グループを作る・記録する・記録を共有する」。ホーム画面に追加するWebアプリとして準備し、HTTPS公開と実機確認は次の作業とする。先の広い範囲案を本書で置き換える。

## 今回の範囲

- グループ名を入力して作成し、招待コードを仲間に渡す。仲間はコードで参加する。
- 日付・種目名・重量・回数・セットを入力し、トレーニング記録として保存する。
- 保存時に選んだ所属グループへ記録を共有し、メンバーが新着順で閲覧する。
- 本人の識別に必要なメール・パスワード登録／ログイン／ログアウトを用意する。
- 自分の保存済み記録を一覧で確認できる。日々の記録はDBに蓄積する。
- 初版はWebページをスマートフォンのホーム画面に追加して使う。アプリ名・アイコン・standalone起動・画面端の安全領域を設定する。保存・共有にはオンライン接続が必要で、オフライン同期やService Workerによるデータキャッシュは含めない。

SCORE、ランキング、AI、スタンプ、コメント、Push通知、分析、記録の編集・削除、グループの退出・管理機能、ネイティブモバイルアプリ、公開環境へのデプロイは後続Issueとする。

## 基本ルール

- グループは作成者もメンバーになる。複数のグループへ参加できる。
- 招待コードは推測しにくいランダム値。コードを知るログイン済みユーザーが参加できる。
- 同じグループへの再参加は重複メンバーを作らない。
- 共有先は保存操作の直前に明示する。所属していないグループには保存・閲覧できない。
- 共有先を選ばず自分だけの記録としても保存できる。過去の個人記録を参加後に自動共有しない。
- 記録は1回のトレーニング単位で保存し、同じ日でも複数件を保持する。
- 種目・セットの入力途中は共有しない。記録保存と共有先の確定は1トランザクションで行う。
- 通信再試行による重複保存を防ぐため、クライアントが発行する記録UUIDを使う。同じUUIDで別の内容を送った場合は競合エラーとする。
- 自分の記録と、現在所属しているグループへ共有された記録だけ閲覧できる。メールアドレスや認証情報を他のメンバーへ返さない。
- 一覧は50件ずつ取得できる。記録日は降順、同日の記録は保存日時の降順で表示する。グループの活動は保存日時の降順で表示する。
- グループ表示は5秒間隔で取得し、ブラウザの非表示中は停止する。通信失敗時は明示し再試行できる。

## 入力条件

- 表示名: 前後空白を除いた1〜20文字。
- グループ名: 前後空白を除いた1〜40文字。
- 記録日: 2000-01-01以降、日本時間の今日まで。
- 1記録につき1〜20種目、種目名は前後空白を除いた1〜60文字。
- 1種目につき1〜30セット。重量は0〜1,000kg（小数1桁まで）、回数は1〜1,000の整数。0kgは自重種目に使う。
- 空・不正な数値・上限超過は保存せず、入力エラーを表示する。

## 技術と境界

- 現行のNext.js／TypeScript、FastAPI、Supabase PostgreSQL／Authを利用する。
- WebはSupabase Authでログインし、APIへBearerトークンを送る。APIはAuthサーバーで検証したユーザーIDを利用する。
- WebからDBを直接操作しない。業務ルールとアクセス制御はFastAPI側へ置き、DBの公開テーブルではRLSを有効にして直接アクセスを拒否する。
- ブラウザのAPIは同一オリジンの `/api` を使い、Next.jsからFastAPIへ転送する。APIはWeb専用Cookieに依存しない。
- DB接続先とサーバー用認証設定はbackendの環境変数に置く。frontendには公開可能なSupabase URL・キーのみを置く。
- ローカルSupabaseは `gotore` 専用のプロジェクト名とポートを使い、同じマシンの別プロジェクトから分離する。
- 画面は参考画像の日本語・ライトテーマ・赤を基調とし、スマートフォンで操作できるようにする。

## API

| メソッド・パス | 内容 |
| --- | --- |
| GET /api/me | 本人の表示名・ID |
| GET /api/groups | 自分の所属グループ |
| POST /api/groups | グループ作成・作成者の参加 |
| POST /api/groups/join | 招待コードで参加 |
| GET /api/groups/{id} | グループ情報とメンバー |
| GET /api/groups/{id}/workouts | メンバー向け共有記録一覧 |
| GET /api/workouts | 自分の記録一覧 |
| POST /api/workouts | 記録保存と選択したグループへの共有 |
| GET /api/health | 既存のヘルスチェック |

health以外は認証必須。入力不正は422、未認証は401、他グループへのアクセスと不明な招待コードは404、保存IDの競合は409、設定不足・外部基盤の障害は503。
取得APIはキャッシュしない。

## データ

- profiles: SupabaseのユーザーIDと表示名。
- groups: グループID、名称、作成者、招待コード、作成日時。
- group_members: グループIDとユーザーIDの組、参加日時。
- workouts: 記録ID、本人ID、共有先グループID（個人記録ならnull）、記録日、種目・セットのJSON、保存日時。

グループ作成と作成者の参加、記録の保存はそれぞれ原子的に処理する。外部キー・一意制約・入力に対応したCHECK制約で整合性を守る。
