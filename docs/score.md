## 1. 合意済みの方針

- 成長率の大きさではなく、最近の自分の実績への到達度を評価する。自己ベストを更新しなくても満点を取れる。
- 量の指標は総負荷（重量kg × 回数の合計）。
- 比較に使うトレーニング履歴は最大1か月。以下では直近30日と定義する案を置く。
- 目標は個人単位。未設定の場合は標準目標を適用する。
- グループは配点を設定する。目標適合度のLLM評価を所属グループ間で共通利用する。
- 目標変更を理由に過去のトレーニングを採点・再採点しない。採点済みの記録は当時の目標と点数を保持する。
- 継続性、出力、総負荷、目標適合度を分ける。

## 2. 今回提案する初期値

以下は今回の仮案であり、合意済みの数値・科学的に検証済みの採点基準ではない。

| 設定 | 初期案 |
| --- | --- |
| 個人目標 | 有効な目標を1つ |
| 標準目標 | 筋トレを継続し、自分に合ったトレーニングを積み重ねる |
| 数値基準の参照期間 | 対象記録日の前日までの直近30日 |
| 継続性の集計期間 | 直近28日、7日ずつ最大4区間 |
| 継続性の満点条件 | 各7日区間で2実施日 |
| 出力・総負荷の満点条件 | 基準の95%以上 |
| 基本配点 | 継続性30%、出力20%、総負荷40%、目標適合度10% |
| 点数上限 | 各項目100点、総合点100点 |
| 表示 | 内部では精度を保持、表示時に四捨五入。総合点は整数 |

週2日・95%・配点はサービス上の採点パラメータ案であり、トレーニングの処方ではない。初版のグループ設定は配点に絞り、項目の式・満点条件を共通にする。

## 3. 採点対象と基準回

採点単位は終了済みトレーニング1回。1セット以上の保存を必要とし、空の開始セッション・未送信セット・生存確認だけでは採点しない。旧形式の確定記録も数値の参照に使用できる。導入前の記録へSCOREを一括付与する処理は作らない。

日付は既存のperformed_onをJSTの日付として使う。日付Dの採点なら、数値基準の候補はD-30日からD-1日まで。今回と当日の別記録は基準候補に入れない。採点時点で保存済みの履歴だけを用いる。

基準回Bは、次の条件を満たす中で総負荷が最大の1回とする。

1. 本人の記録である。
2. 上記の参照期間内で、確定済みである。
3. 今回と種目構成が同じである。

種目構成は、前後空白除去後の種目名を重複除去して並べた集合で識別する。種目の順番・セット数・重量・回数はキーに含めない。同名行のセットはまとめる。総負荷が同じなら記録日、開始日時（旧記録は保存日時）、IDの降順で1回に確定する。

**出力も総負荷も、この同じ基準回と比較する。** 最高重量の日と最多セットの日を別々に使い、実在しない組み合わせを要求しないための提案である。

この選び方は「総負荷が最大の回」を最高のトレーニングの代理とするもので、トレーニングの質そのものを証明しない。種目構成が同じでも目的や回数帯が違う場合には、完全に同条件とはいえない。

## 4. 総負荷 V

今回の総負荷をv、基準回の総負荷をb_vとする。

v = Σ（各セットの重量kg × 回数）

V = 100 × min(1, v / (0.95 × b_v))

b_vが0または基準回がない場合は未評価。0除算を行わず、0点や自動満点を付けない。

| 基準回の総負荷 | 今回の総負荷 | V |
| --- | --- | --- |
| 6,000kg | 6,000kg | 100.0 |
| 6,000kg | 5,700kg | 100.0 |
| 6,000kg | 5,400kg | 94.7 |
| 6,000kg | 3,000kg | 52.6 |

上限を超えた実績は記録として残すが、点数は100で止める。ウォームアップ区分は現在保存されていないため、この案では保存済みセットを一律に含む。

## 5. 出力 I

種目ごとに、今回と基準回それぞれの最高推定1RMを比較する。実重量の95%を要求する式ではなく、回数を含む推定値の比である。

推定1RMは既存実装と同じ規則を維持する。

- 正の重量・1回: 実重量
- 正の重量・2〜10回: 重量 × (1 + 回数 / 30)
- 結果は小数1桁で四捨五入
- 重量0、11回以上: 算出対象外

種目eの今回最高推定1RMをp_e、基準回の値をb_eとする。

I_e = 100 × min(1, p_e / (0.95 × b_e))
I = 対象種目のI_eの単純平均

種目を平均する前にそれぞれ100点で上限を設ける。他の種目の低い到達度を、1種目の極端な更新で打ち消さない。

初期案では構成内の全種目について今回・基準回の両方に有効な推定1RMがある場合だけIを確定する。不足があればIは未評価とし、一部だけを除いて満点を作らない。

例: 基準回100kg相当、今回95kg相当ならI_e=100点。基準回自体が高回数中心の場合、Iは未評価となり得る。この制約を避けたいグループは出力の配点を0にできる。

これは基準回の出力への到達度であり、実際の限界・疲労・フォームの品質を測る値ではない。

## 6. 継続性 C

対象日Dを含む直近28日を、D-6〜D、D-13〜D-7、D-20〜D-14、D-27〜D-21の4つの7日区間に分ける。日付をまたいだセッションのセット別日時は現行DBにないため、各記録のperformed_onで数える。

各区間の実施日数をn_i、満点になる実施日数をq=2とする。同じ日の記録が複数あっても1日と数え、採点対象の今回の記録も含む。

C = (100 / k) × Σ[i=1..k] min(1, n_i / q)

通常はk=4。初回実施日から28日未満の場合は、初回実施日より前の日を含まない完全な7日区間だけを使う。k=min(4, floor(観測日数/7))。k=0なら「継続性を計測中」として未評価にする。初回実施日は観測開始日のメタデータとして保持し、計算対象の実施日は直近28日以内に限定する。

| 4区間の実施日数 | C |
| --- | --- |
| 2・2・2・2日 | 100 |
| 2・2・2・0日 | 75 |
| 7・0・0・0日 | 25 |

活動日数は1セット以上ある確定記録から求める。LIVE/TODAY表示の人数・生存確認は使わない。1セットだけでも1日になることはこの単純案の限界であり、「採点対象となる実施日の最低条件」は検証事項として残す。

## 7. 目標適合度 G

標準目標は「筋トレを継続し、自分に合ったトレーニングを積み重ねる」。特定の部位・記録更新・毎日の実施を暗黙の必須条件にしない。標準目標もバージョン付きの目標として扱う。

目標設定時に、記録から確認できる条件を2〜4件の評価基準として保存する。自由記述目標からの基準案作成にLLMを使えるが、必要な頻度・負荷・達成期限を勝手に補完せず、不明な条件は設定時に確定する。標準目標には事前定義した基準を適用する。

採点時のLLMは、固定された条件ごとに次の判定を返す。

| 判定 | r_j |
| --- | --- |
| 満たす | 1 |
| 一部満たす | 0.5 |
| 満たさない | 0 |
| 情報不足で判定できない | null |

G = 100 × Σ r_j / 条件数

例: 2条件が「満たす」「一部満たす」なら75点。nullがある場合はGを未評価とし、残りの条件だけで満点にしない。点数への換算・範囲の検証はAPI側で行う。

条件は目標と対象種目・配分・明示した計画の対応を中心にする。既存の継続性・出力・総負荷を同じ定義でもう一度加点しない。目標結果の達成確率や筋肥大の程度は採点しない。休息・負荷を抑える日・維持・新しい種目への挑戦を、それだけで不適合としない。

**LLMに見せる達成評価用の履歴は、直近最大30日かつ同じ目標バージョンの記録だけ。** 新目標より前のトレーニングを新目標で判定しない。分割メニューは今回だけで断定せず、条件で定めた観測期間と計画を参照する。新目標直後で観測期間が足りない条件は情報不足として扱う。

目標変更前の数値実績をI/Vの基準に使うことと、新目標で昔の行動を再採点することは別とする。この案では条件を満たす直近の数値実績はI/Vの参照に残す。

標準目標の最終的な評価条件、小型モデルの採用可否は実記録の例で検証する必要がある。一般目標は条件が広く満点になりやすく、個人目標との難易度差も解消済みとはみなさない。そのためGの初期配点を10%とする案を置く。

## 8. 総合点 S

各項目は0〜100点。グループの重みw_C、w_I、w_V、w_Gは0以上、合計1とする。

S = w_C × C + w_I × I + w_V × V + w_G × G

初期案:
S = 0.30C + 0.20I + 0.40V + 0.10G

| 項目 | 実績・判定 | 点数 |
| --- | --- | --- |
| 継続性 | 2・2・2・0日 | 75 |
| 出力 | 基準100kg相当に対して95kg相当（単一種目の例） | 100 |
| 総負荷 | 基準6,000kgに対して5,400kg | 94.7368… |
| 目標適合度 | 2条件が満たす・一部満たす | 75 |

S = 22.5 + 20 + 37.8947… + 7.5 = 87.8947… → 表示88点

重み0の項目は評価結果を必要としない。重みが正の項目が1つでも未評価なら総合点は未確定とし、取得済みの内訳だけを表示する。未評価を0点にしたり、残りの配点を自動で引き上げたりしない。

グループ配点を変更してもGの再採点は不要。配点は次の週から適用し、過去の集計で使った配点バージョンを保持する案とする。週間・月間のランキングの集約方法は本案では未確定で、1回ごとの点数の単純合計を既定としない。

## 9. 目標変更と採点回数

- トレーニング開始時に有効な目標バージョンをその記録へ固定する。
- 進行中に目標を変更しても、その記録は開始時の目標で終了する。新目標は次に開始する記録から適用する。
- 目標変更後、過去記録への新規採点・再採点・LLM呼び出しは発生させない。
- 1トレーニングの終了確定後、個人共通のGを原則1回生成し、全所属グループで共用する。
- 同じ記録を開く、グループへ参加する、配点を変える操作ではLLMを呼ばない。
- LLM通信失敗は「採点待ち」。再試行は同じ入力・目標・基準を用い、正常に保存できた結果を再利用する。
- 記録訂正は目標変更と区別する。当該記録を再評価する場合も、採点時の目標・基準を使う。過去訂正による後続スコアの一括再計算は初版では行わず、スコアを「採点時の評価」として保存する。
- 記録削除時は当該スコアも表示・ランキング対象から外す。

## 10. 最小の追加データ

| 保存対象 | 主な内容 |
| --- | --- |
| 個人目標 | 本文、標準目標フラグ、評価条件、適用開始、バージョン |
| 記録の採点結果 | workout_idとrevision、目標バージョン、C/I/V/G、状態、理由 |
| 採点の根拠 | 基準回IDとrevision、基準値、参照した入力のスナップショット、採点日時 |
| 採点の版 | 算式・プロンプト・モデルのバージョン |
| グループ配点 | 各項目の重み、適用開始、バージョン |

計算はFastAPIのdomainへ置く。既存の記録×種目の集計をI/Vの基準選択に利用できる。LLMへの入力は本人の目標と必要な本人データに絞り、グループには共有が許可された点数・理由だけを返す。個人目標の本文・非公開記録・メモを点数と一緒に自動公開しない。

## 11. この案の制約と次の確認

- 同じ種目構成に絞るため、種目を1つ追加・削除すると基準回がなくなりやすい。必要なら後続で本人のメニュー区分を導入する。
- 自重を0kgで記録する種目、高回数だけの記録はV/Iの一部を計算できない。推測で体重や1RMを補わない。
- 最大総負荷の1回が誤入力や例外的な高負荷だと、30日間基準に残る。最大値方式の性質として扱い、外れ値確認や復帰時の基準作成は後続検討とする。
- 同じ種目構成でも、回数帯・器具・実施意図が違う場合は比較の精度に限界がある。
- LLM評価は固定基準でも完全に同じ判断が保証されない。代表例に対する人の判断との一致、繰り返しのぶれ、入力不足の判定を検証して採用モデルを決める。
- 入力可能な上限と、採点上の有効な実績は同義ではない。初版で不正入力や水増しを完全に防げるとはみなさない。

今回、満点境界、上限、継続性の分散・集中パターン、総合88点の計算例をPythonのDecimalで確認した。LLM採点・DB/API・実アプリの動作は未実装・未検証。
