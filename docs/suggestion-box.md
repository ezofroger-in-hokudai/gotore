# 設定の目安箱（#189）

2026-09-20のユーザー指定「まず実装、設定から送信、見る場所はどこでもよい」を適用する。初版は既存Supabaseに保存し、運営のSupabaseプロジェクト管理者がTable Editorで確認する。Google連携やアプリ内管理者ロールを新設しない。

## 投稿

設定 → サポート → 目安箱。ログイン済みユーザーが本文1〜2000文字（前後の空白を除く、Unicodeコードポイント数）を送る。画面に「内容と送信者は運営管理者だけが確認します」と示す。送信者は認証済みID・現在の表示名をサーバーで設定する。メール・端末情報・私的メモを自動収集しない。

送信中の二重操作を防ぎ、成功時に本文を消して完了を表示する。失敗時は入力と送信IDを保持し、同じ内容の再試行は同じIDで行う。送信結果不明時に本文を変更すると別投稿になり得るため、失敗後は同じ本文での再試行とする。閉じても設定画面にいる間は入力/送信状態を保持する。設定から離れたり再読み込みすると未送信内容は失われる旨を入力欄で案内する。端末への永続化は初版の対象外。

## API・保存・権限

`POST /api/suggestions` に `id`（UUID）・`content` を渡す。201は投稿IDと作成時刻だけを返す。余分なフィールドは拒否。投稿者IDは認証から取得し、本文をログへ出さない。ユーザー別の同一ID/同一本文再送は元の受付結果、内容が異なれば409。同一ユーザーの保存を直列化し、過去24時間に新規20件まで、超過は429。既存IDの再送は上限に含めない。

`public.gotore_suggestions` に保存。RLSを有効にし、PUBLIC/anon/authenticatedの権限を剥奪、公開ポリシーや読み取りAPIを用意しない。投稿者本人も他のユーザーも投稿後の一覧・詳細を読み出せない。グループオーナーも同様。APIは既存のバックエンドDB接続で認証後に作成する。アプリへ新しい管理キーは渡さない。

## 運営管理者の確認手順

1. 対象環境のSupabase Dashboardへ管理者アカウントでログインする。
2. Table Editor → public → gotore_suggestionsを開く。
3. created_atを新しい順にし、content・display_name・user_idを確認する。本文はテキストとして読み、記載されたURLを自動実行しない。
4. 対応済みの整理には管理画面でstatusをnew/read/resolvedに変更できる（利用者向け返信ではない）。

Supabaseプロジェクトへのアクセスを持つ運営担当だけが閲覧する。アプリの一般ユーザーにDashboardアクセスや管理キーを配布しない。担当者の閲覧権限を外す場合はSupabase側の組織/プロジェクトアクセスを削除する。初版ではアプリ内の管理画面・返信・添付・外部通知・投稿者の履歴は提供しない（拡張の追跡先は#189）。

保存期限による自動削除は設けず、不要になった投稿は管理者が対象を確認して削除する。アカウント削除時は投稿もCASCADEで削除する。管理者が投稿を削除した後の同じIDの再送は新規として扱われる。

## 反映・検証

migration `20260920070000_suggestions.sql` をAPI/Webより先に適用する。既存テーブル・データは変更しない。新環境変数・外部アカウント・依存追加なし。

DB/APIテストで認証・入力・同一ID再送・他ユーザー分離・連投上限・直接DBアクセス禁止を確認する。ブラウザで設定からの送信、失敗再試行、閉じて再表示、空白入力、幅320/390/430pxを確認する。Supabase管理画面そのもののUIは自動テストせず、管理者相当のDB読取で投稿が見えることを確認する。
