# スタンプ・トレーニング開始通知

現在の仕様は[採用デザインと操作](design/activity-notifications.md)を参照。今回の依頼により、従来のスタンプ表示に加えて全画面通知、開始通知、Web Pushを実装した。

## アプリ内

ログイン中のWorkspaceに一つの受信キューを置き、可視状態では2秒周期・復帰時に取得する。最初の到着から追加の集約待ちは設けない。画面切替でもキューと表示時間を引き継ぐ。スタンプは個別650ms、まとめ2.5秒。未表示が5送り主以上または10件以上ならまとめ、届いた種類のみ数を横一列に出す。上48px以上の明確なスワイプで閉じ、操作中はタイマーを止める。

開始は採用Cグラデーションの実線チケット。人数・入る限りの顔・3人未満の名前を表示。最初の5秒内の追加は同じカードを更新し、時間を延長しない。画面タップで閉じ、START/RESUME等の本来の操作も同じタップで行う。初期設定はホーム復帰時。全画面即時／記録中はセット保存後も選べる。終了・共有解除・共通所属喪失・5分のLIVE期限切れを除外する。

設定はアカウント単位でDB保存。スタンプ／開始のアプリ内表示、OS配信、表示タイミング、アプリ内の振動／音を分離する。振動オン・音オフが初期値。iPhoneではアプリ内の標準Vibration APIは使えない。

## Web Pushの運用

Androidの対応ブラウザ、iOS/iPadOS16.4以降のホーム画面に追加したPWAが対象。HTTPSが必要。許可は設定のボタンから要求し、起動時には要求しない。[WebKitの対応条件](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)。

1. `make db-migrate`で`20261001030000_activity_notifications.sql`を適用する。
2. `cd backend && uv run --locked python -m app.services.notification_keys`で`.env.vapid`を新規生成する。0600で保存し、既存ファイルは上書きしない。内容をAPI・ワーカー両方の秘密環境変数へ設定する。秘密鍵は公開・コミットしない。
3. `VAPID_SUBJECT`を管理者の連絡先（`mailto:`またはHTTPS）に設定する。公開鍵／秘密鍵は`.env.example`を参照。鍵を変えると既存購読の再登録が必要。
4. APIに加えて`make notifications-worker`を永続プロセスとして起動する。APIのリクエストだけ／フロントのホスティングだけでは、閉じたアプリへ配信できない。ワーカーにも`DATABASE_URL`が必要。
5. アプリの「設定→通知→この端末の通知を有効にする」で購読を登録する。

DBトリガーがスタンプ／共有された新規セッションから受信者ごとのイベントを生成する。グループ重複は排除する。作成済み購読への配信を別テーブルに永続化し、ワーカーが権限・未表示・設定・LIVEを再検証する。前景中は保留、表示済みは配信を取り消す。ネットワーク失敗は最大10回まで指数的に再試行、404/410の購読は削除する。再起動でも未配信を保持する。

OS通知には名前・記録・スタンプ種類を送らず、種類と件数だけを送る。「誰かからスタンプが届きました」「誰かがトレーニングを開始しました」。tagで種類ごと一枚に更新し、タップ先はホーム。OSへ配信してもアプリ内の表示済みにはしない。OSの音・振動は端末設定に従う。ログアウト時にそのブラウザの購読を解除する。同じendpointのアカウント変更でも旧所有者の配信を残さない。

## APIと検証

認証必須の`/api/notifications`配下に`settings` GET/PUT、`inbox` GET、`seen` POST、`push-key` GET、`subscription` PUT/DELETE、`presence/{id}` POSTを追加。Push購読のURLは対応サービスのHTTPSだけ、鍵のサイズ・形式も検証する。確認保存は受信者本人のイベントのみ。通知テーブルはRLSを有効にしてクライアントからの直接操作を禁止する。

テストは`backend/tests/test_notifications.py`、`frontend/tests/unit/notification-*.test.ts`、`frontend/tests/e2e/activity-notifications.spec.ts`。Android/iOS実機での閉じた状態の配信・通知センター・タップ遷移は、公開環境に鍵とワーカーを設定して別途確認する。ブラウザのエミュレーションだけで実機成功とはしない。
