# 部位を表示する総負荷ヒートマップ

2026-09-13の画面比較 #136 / PR #137への追加指定。日付のマスに部位を表示し、上の部位フィルターは横一列・折り返しなしで採用する。「現在の分類で過去も表示し直す」をユーザー回答で採用した。

- 本人の種目リストの**現在の主部位**に、同名種目の総負荷とセット数を1度だけ計上する。補助部位には重複計上しない。分類変更は次回の取得で過去の記録にも反映する。
- 未設定・削除済み候補は未分類。標準名への推測による再分類や、他のユーザーの分類での補完をしない。記録本文や種目の分類データを書き換えない。
- 上部に「すべて」と各部位・未分類のボタン。横スクロールでき、選択は色と押下状態で示す。部位切り替えは取得済みの同じ月データから行い、追加通信しない。
- 日付のマスは日付・部位・総負荷kg。複数部位は部位名1つと残りの数（例: 胸+1）。部位名は既存分類順で表示し、日付選択でその日の全内訳（部位・セット数・kg）を表示する。読み上げには省略せず全ての部位名を含める。
- 選択部位でカレンダーと要約を絞る。記録がない日は灰色、自重0kgの記録は青。色尺度は選択中の部位・月の最大値を基準にする。紫は使わない。
- 日付選択は既存の日別記録一覧を開く。同日の記録本文は全種目を表示し、部位フィルターはカレンダー集計を対象にする。部位を変えたら日付選択を解除し、違う部位での前の日付を持ち越さない。月変更も日付選択を解除する。
- 「総負荷カレンダー」の表示見出しは省き、月・数値・凡例と読み上げ名を残す。他の重複文言の整理は [ui-copy.md](ui-copy.md)。

## APIと高速化

既存の `GET /api/workouts/activity?month=YYYY-MM` の各日へ `body_parts` を追加する。各部位は `body_part`（コードまたはnull）・`volume`・`set_count`・`workout_count`。従来の日別/全体合計も保持する。部位別の記録件数はその部位を含む記録の件数で、全体件数は複数部位で重複させない。

月・本人で絞った既存統計テーブルと本人の種目分類を結合し、日別全体と部位別を1回のSQLで集計する。全履歴JSON・部位ごとのHTTP・新規DB・migrationは追加しない。既存の月別先読み、保持・再確認・エラー・保存後の更新を共用する。分類の変更後も、カレンダーへの再訪時の再確認で最新を取得する。

旧応答で内訳がない場合は全体のみ表示し、部位を推測して埋めない。0件と取得失敗を区別し、失敗時は未記録に見せず、再試行で取り直す。

## 検証

本人限定、補助部位の非加算、同日の複数記録・複数主部位・同じ主部位の複数種目、現在分類への再分類、削除後の未分類、自重0kg、記録訂正・削除、月境界、SQL回数を検証する。画面では折り返しなし、横スクロール、選択状態、部位の省略と日別内訳、月変更、空部位、通信回数と保存共有を確認する。
