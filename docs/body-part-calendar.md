# 部位を表示する総負荷ヒートマップ

2026-09-13の画面比較 #136 / PR #137への追加指定。日付のマスに部位を表示し、上の部位フィルターは横一列・折り返しなしで採用する。「現在の分類で過去も表示し直す」をユーザー回答で採用した。

- 本人の種目リストの**現在の主部位**に、同名種目の総負荷とセット数を1度だけ計上する。補助部位には重複計上しない。分類変更は次回の取得で過去の記録にも反映する。
- 未設定・削除済み候補・旧全身はその他。標準名への推測による再分類や、他のユーザーの分類での補完をしない。記録本文は書き換えない。分類データの移行は [exercise-body-parts.md](exercise-body-parts.md) に従う。
- 上部に「すべて」と胸・背中・脚・腕・肩・腹筋・お尻・その他の固定9ボタン。11px文字と小さい余白で横一列に収め、横スクロールしない。高さ44pxを保ち、選択は色と押下状態で示す。部位切り替えは取得済みの同じ月データから行い、追加通信しない。
- 日付のマスは日付・部位・総負荷kg。複数部位は部位名1つと残りの数（例: 胸+1）。部位名は既存分類順で表示し、日付選択でその日の全内訳（部位・セット数・kg）を表示する。読み上げには省略せず全ての部位名を含める。
- 選択部位でカレンダーと要約を絞る。記録がない日は灰色、自重0kgの記録は青。色尺度は選択中の部位・月の最大値を基準にする。紫は使わない。
- 日付選択は既存の日別記録一覧を開く。同日の記録本文は全種目を表示し、部位フィルターはカレンダー集計を対象にする。部位を変えたら日付選択を解除し、違う部位での前の日付を持ち越さない。月変更も日付選択を解除する。
- 「総負荷カレンダー」の表示見出しは省き、月・数値と読み上げ名を残す。他の重複文言の整理は [ui-copy.md](ui-copy.md)。

## APIと高速化

既存の `GET /api/workouts/activity?month=YYYY-MM` の各日へ `body_parts` を追加する。各部位は `body_part`（8分類のコード）・`volume`・`set_count`・`workout_count`。従来の日別/全体合計も保持する。部位別の記録件数はその部位を含む記録の件数で、全体件数は複数部位で重複させない。

月・本人で絞った既存統計テーブルと本人の種目分類を結合し、日別全体と部位別を1回のSQLで集計する。全履歴JSON・部位ごとのHTTP・新規DBは追加しない。8分類の統一には上記migrationを追加する。既存の月別先読み、保持・再確認・エラー・保存後の更新を共用する。分類の変更後も、カレンダーへの再訪時の再確認で最新を取得する。

旧応答で内訳がない場合やnull/full_bodyの旧内訳が残る場合は全体のみ表示し、部位を推測して埋めない。0件と取得失敗を区別し、失敗時は未記録に見せず、再試行で取り直す。

## 検証

本人限定、補助部位の非加算、同日の複数記録・複数主部位・同じ主部位の複数種目、現在分類への再分類、削除後のその他、自重0kg、記録訂正・削除、月境界、SQL回数を検証する。画面では折り返しなし、横スクロールなし、選択状態、部位の省略と日別内訳、月変更、空部位、通信回数と保存共有を確認する。

## 部位の複数選択と文言整理（#140）

ユーザーの追加依頼により、胸と肩などの同時選択を採用する。選択済み部位を再タップすると解除。「すべて」は選択解除、最後の1部位を解除した場合も全体表示へ戻る。選択は月変更でも保持し、日付選択は部位/月の変更で解除する。8部位すべてを個別に選んだ場合も全体と同じ合計になる。

選択した現在の主部位の総負荷・セット数を合算する。活動日数は日付の和集合、記録件数は選択したいずれかの部位を含むトレーニングの和集合とし、複数部位を含む1記録を二重に数えない。日付タップ後の内訳・記録本文は従来どおりその日の全体を示す。

各日のAPIに `workout_groups: [{body_parts: [部位コード…], workout_count: 件数}]` を追加する。同じ部位の組合せを持つトレーニングを集約し、IDや記録本文は追加しない。月の1回のSQLで取得し、Webではいずれかの選択部位を含む組合せの件数を加算する。既存の単独部位・全体の数値は保持する。追加migrationは不要。

旧API/キャッシュで組合せ情報がない場合も総負荷とセット数の複数選択は可能。1部位だけ、または当日の全部位を選んだ場合は既存の正確な件数を使う。それ以外で重複が判定できない件数は「—」とし、0や単純加算で推測しない。部位内訳そのものがない旧応答は従来どおり全体表示にする。互換APIを先に公開すれば通常表示の件数も確定する。

凡例バーと常設の算式説明は削除し、総負荷・k表記・選択部位の月内最大値に対する色の意味は既存の使い方へ移す。日別の色・数値・読み上げ情報は維持する。
