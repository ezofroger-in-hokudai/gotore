# 招待コードの再発行（#20）

画面文言は2026-09-08の[簡略化方針](ui-copy.md)を優先する。説明は初回ガイドに集約し、以下の業務ルールを維持する。

2026-09-08のユーザー指示（一般的に判断できる仕様は実装してよい）に基づく追加範囲。[初版の参加・共有ルール](standard-v0.1-scope.md)を維持する。

- オーナーがグループ画面から再発行を開き、旧コードが使えなくなることを確認して実行する。通常メンバー・非所属・未認証には許可しない。
- 再発行によって旧コードを無効化し、ランダムな新コードを1つ発行する。招待停止状態や有効期限は今回導入しない。
- 既存メンバー・グループ名・過去記録は保持する。新コードを知るログイン済みユーザーは、既存の参加ルールで参加できる。
- APIは `POST /api/groups/{id}/invite-code`。本文は `expected_invite_code` のみ（12桁の16進数、前後空白を除去し大文字化）。オーナー以外・不明なグループは404、未認証401、入力不正422。
- グループ行をロックして、期待コードと現在コードが異なる場合は409。画面には変更済みの可能性を示し、現在のコードを再取得できる。通信失敗時も成功扱いにせず再取得を案内する。
- 参加処理もグループ行をロックする。参加と再発行が同時の場合はロック獲得順に処理し、再発行完了後に旧コードから新たに参加しない。
- コードは従来と同じ暗号学的乱数の12桁。元と同じ値や一意制約の衝突時は最大5回再生成し、発行できなければ503。既存コードを壊さない。
- 成功後は新コードを表示し、コピーできる。確認中のキャンセルは変更しない。グループの切り替えでは確認・エラー状態を持ち越さない。

検証: オーナー／メンバー／非所属／未認証、旧コード拒否・新コード参加、既存所属・記録保持、競合・乱数衝突・失敗時のロールバック、確認／キャンセル／通信失敗／再取得、390px表示を確認する。DB列やmigrationの追加は不要。
