# グループ招待リンク・コード

画面文言は2026-09-08の[簡略化方針](ui-copy.md)を優先する。説明は初回ガイドに集約し、以下の業務ルールを維持する。

2026-09-08のユーザー指示（一般的に判断できる仕様は実装してよい）に基づく追加範囲。[初版の参加・共有ルール](standard-v0.1-scope.md)を維持する。

- グループメンバーはリンクまたはQRを共有できる。招待は発行から7日後に期限切れとなり、それまでは複数人が使える。
- 新しい招待を発行しても、それ以前の招待はそれぞれの期限まで有効とする。既に所属する人が同じリンクを再度開いても所属を増やさない。招待を作った人がグループから抜ける・退出させられる場合は、その人が発行したリンクを削除する。グループ削除でも全リンクが失効する。
- 参加前にグループ名、メンバー数、メンバーの表示名と役割を1ページで表示し、参加操作時に招待を再検証する。「参加後の記録から共有されます」と案内する。有効なリンクを持つログイン済みの人にだけ見せ、写真・活動日時・記録は公開しない。
- `POST /api/groups/{id}/invites` は所属メンバーに限り、新しいURL用トークンと有効期限を返す。以前のリンクは置き換えない。原文は保存せずSHA-256ハッシュを保存する。
- 互換用の `POST /api/groups/{id}/invite-code` は旧画面からの再発行に残す。期待コードと現在コードの比較・旧コード無効化・ロックは維持する。
- 招待発行・参加処理は同じグループ行をロックする。発行と参加が同時の場合はロック獲得順に処理し、期限切れや旧仕様で使用済みになった招待からは参加しない。
- URL用トークンは暗号学的乱数32バイトから生成する。一意制約の衝突時は最大5回再生成し、発行できなければ503。従来の12桁招待コードは互換APIで維持する。
- URL用トークンを共有リンクとQRに埋め込む。QRは端末内で生成する。同じ招待画面を開いた際の開発モード再実行でも発行を二重に行わず、リンクとQRが同じ有効トークンを示す。

追加migration `20260927020000_reusable_group_invites.sql` で、招待テーブルのグループ単位一意制約を外し、複数の未期限切れ招待を保持する。従来の使用済みトークンは再有効化しない。

検証: メンバー／非所属／未認証、旧コード拒否・新コード参加、同じリンクで複数人参加、以前のリンクの存続、期限切れ、競合・乱数衝突・失敗時のロールバック、QR・リンクの組み立て、390px表示を確認する。
