# グループ退出・メンバー除外（#7・#19）

画面文言は2026-09-08の[簡略化方針](ui-copy.md)を優先する。説明は初回ガイドに集約し、以下の業務ルールを維持する。

2026-09-08の基本仕様に、2026-09-27のグループ画面合意を追加する。本人の個人履歴は保持し、対象グループとの共有だけを解除する。

- メンバーは自分で退出でき、オーナーは自分以外のメンバーを除外できる。オーナーは先に他のメンバーへオーナー権限を移譲してから退出できる。オーナーの自己除外は拒否する。オーナーはグループを削除できる。
- 実行前に対象者とグループ名、本人履歴は残るがそのグループの共有一覧から消えることを確認する。
- 対象者の、そのグループへ共有した記録だけグループ共有から取り除き、その後所属を削除する。本人の個人履歴・日時・種目・セット・他グループへの共有は保持する。外部キーを維持して一つのトランザクションで確定する。
- グループ削除では、グループに共有された全メンバーの記録をそのグループから取り除く。他グループ共有と各本人の個人履歴は保持する。グループ、所属、招待、グループ単位の統計・活動は削除する。
- 退出後は同じセッションでもグループ詳細・一覧の取得と新しい共有を拒否する。すでに端末で閲覧した内容の回収はできない。
- 有効な招待コードによる再参加は可能。再参加しても以前の記録を自動で共有し直さない。再参加を防ぐには#20の招待コード再発行を利用する。BAN・招待停止状態は導入しない。
- API: `DELETE /api/groups/{group_id}/membership?expected_joined_at=...`（本人）、`DELETE /api/groups/{group_id}/members/{user_id}?expected_joined_at=...`（オーナー）。成功204、権限なし・不明グループ404、オーナーの未移譲退出・再参加後の古い要求409、日時不正422、未認証401。オーナー移譲は `PATCH /api/groups/{group_id}/owner`、グループ削除は `DELETE /api/groups/{group_id}`。
- グループ詳細の各メンバーにjoined_atを返し、操作時の所属と比較する。同じ所属削除の再送は204。新しい参加時刻はclock_timestamp()で生成し、再参加後に古い要求で再び除外しない。
- グループ操作を行ロックで順序付ける。記録保存は所属の共有ロック、除外・退出は所属の更新ロックを先に取得し、保存との競合で履歴を消失させない。
- ローカル下書きは保持する。退出した共有先では保存不可として、本人用や別の所属先を選び直す。所属一覧の再取得後に無効な選択を表示に使わない。
- 退出・除外・削除はグループ行をロックし、記録保存・招待参加・オーナー移譲・削除との競合を一つのトランザクション内で順序付ける。グループ削除時は旧式の単一group_idをNULLへ戻し、個人記録を保持してからグループを削除する。
- #6の編集は共有先を変更しないため、解除済みの記録を再共有しない。
- スタンプは未実装（他担当#12）。追加時に所属と共有解除に応じた閲覧制御が必要。
