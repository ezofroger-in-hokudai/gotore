# 段階的な実装とモバイル対応の方針

2026-09-07のユーザー方針に基づき、現行のNext.js／FastAPI基盤で必要な機能から実装し、毎週追加・修正します。
この文書は開発方針です。ユーザー指定の初版の範囲とMOCK資料からの変更点は [standard-v0.1-scope.md](standard-v0.1-scope.md) に記録しています。
初版はWebページをスマートフォンのホーム画面へ追加して使うオンラインWebアプリです。ネイティブアプリ化は後続とし、まずWebの操作・保存・共有を改善します。

## 最初の実装で優先すること

- 利用者が操作して価値を確かめられる最小単位を完成させる。
- 実際に使った結果をIssueへ戻し、次の週に改善する。
- 先送りする機能・制約はIssueで追跡する。
- 認可、共有範囲、入力制約、データ整合性、必要なテストを初版の受け入れ条件に含める。
- 汎用化や新しい依存の追加は、その週の機能に必要な分にとどめる。

## 責務の配置

| 責務 | 現行の配置先 | 境界 |
| --- | --- | --- |
| 画面・操作 | `frontend/src/app`・`components`・`features` | 入力補助や表示。採点・公開範囲などの最終判断はAPI側 |
| API通信 | `frontend/src/lib` | 接続先・送受信・エラーの扱いをまとめ、画面に散らさない |
| HTTP | `backend/app/api`・`schemas` | 入力・出力の型、検証、ユースケースへの受け渡し |
| 業務ルール | `backend/app/domain` | 採点、記録の制約、共有の条件など。Web画面やDBライブラリに依存させない |
| ユースケース | `backend/app/services` | 記録の確定・共有など、1回の操作に必要な処理を組み合わせる |
| 保存・外部連携 | `backend/app/infrastructure` | DBや外部サービスの実装を閉じ込める |

現在は多くの配置先が空です。機能に必要な単位から実装し、空の抽象クラスや将来用パッケージを先に増やしません。

## Android／iOSへ移植しやすくする

Webと将来のモバイルから同じAPI・業務ルールを利用できる構成を目指します。
Webの画面コードをそのまま移植できるとは想定せず、まずAPIと業務ルールの境界を保ちます。

- 共有する業務処理を、Next.jsだけで利用できるサーバー処理やReactコンポーネントに閉じ込めない。
- APIの入力・出力・エラーを明示し、FastAPIのOpenAPIと実際の応答を一致させる。
- ブラウザのストレージ、通知、画面遷移など、環境に依存する処理は意味のある小さなモジュールに分ける。
- 新しいクライアントが加わるときは、認証・認可、接続先、APIの互換性を仕様として確認する。
- APIやDBを破壊的に変更する場合は、利用中のクライアントと既存データへの影響・移行方法をIssueとPRに記載する。

モバイルのフレームワーク、共通パッケージ、通知、オフライン対応、ストア配布は未決定です。
今の機能に必要な設計を保ち、移植に着手するIssueで要件と方式を決定します。
