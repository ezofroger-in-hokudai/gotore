# ボタン・メモの具体案（#186 / PR #191）

2026-09-21。すべて採用前。[操作できる比較見本](workshop.html)を使って判断する。正本は [既存基準](../design-system.md)。この資料の値を本番実装の確定仕様として参照しない。

## 推奨する出発点

現行の赤と適度な角丸を維持し、役割の数を減らす。ボタンは主操作・補助・文字操作に分ける。メモはAの黄色系を推奨する。セットの数値と文章を見分けやすく、現行の見つけ方を維持できるため。ただし暗色では専用の暗い背景と明るい文字を使う。Bは色を抑えたい場合の比較候補。

シート編集は長文でもセット一覧を押し下げずに書くための検討用。現行のインライン編集より操作が増えるため、今回の推奨に含めて自動採用しない。実際の数値入力、ソフトウェアキーボード、入力への復帰を組み合わせてから判断する。

## 役割と候補値

| 対象 | 候補 | 適用条件 |
| --- | --- | --- |
| 主操作 | 赤塗り・白文字 | 保存、次のセットなど、その操作領域で最も進めたい操作 |
| 補助操作 | 面色・可視の枠 | 戻る、キャンセル、別の進め方 |
| 文字操作 | 下線付きの文字 | 編集、閉じる。文章と混同しない |
| 削除 | 赤文字・赤枠 | 対象・結果の確認内でのみ強調。色だけで意味を伝えない |
| 操作領域 | 幅/高さとも最小48px | ラベルが長ければ折り返して高さを伸ばす |
| 角丸 | ボタン/入力10、メモ12px | 顔画像・スタンプは別役割。箱全体への一律適用はしない |
| 文字 | 本文/ボタン14、入力16、補助12px相当 | remで指定。補助サイズへ重要情報を追いやらない |
| 余白 | 4/8/12/16/24/32px | 部品内12〜16、同じ操作群8、説明節24〜32。記録画面全体は別途評価 |
| 面と枠 | 通常の区切り線と操作部品の枠を別トークン | 薄い線だけで入力欄を識別させない |

見本の`workshop.css`に候補トークンを集約。暗色の主ボタンは白文字の読みやすさのため現行より暗い赤 `#bd2529` を試す。デモ外枠の大きな見出し・節間・カードはアプリの候補値ではない。

## 状態と操作の契約案

| 状態 | 見た目・操作 | 避けること |
| --- | --- | --- |
| 通常 | 役割に応じた色・枠・ラベル | 同じ保存操作を画面ごとに別の形にする |
| 押下 | 明度を下げる。位置は動かさない | タップでレイアウトがずれる |
| フォーカス | 外側の輪郭で識別 | outlineを消す |
| 無効 | 薄くする、操作を受け付けない | 薄い色だけで送信中と区別させる |
| 保存中 | 「保存中…」、重複操作を抑制 | 成功する前に保存済みと表示 |
| 失敗 | フォーム内に理由と再試行方法、入力保持 | シートを閉じる、入力を消す |
| 空 | メモなしと示す。空文字で再編集 | 「メモはありません」を保存内容に混ぜる |
| 成功 | 成功応答後に本文更新・編集を閉じる | 通信結果と独立した見た目だけの成功 |

独立デモは通信をせず0.5秒で結果を模擬する。下書きは種目/今回を分けてメモリ内で保持し、再読込で初期化する。本番の本人限定・1000文字・競合検知・端末への下書き保存は既存の [メモ仕様](../private-workout-memo.md) に従う。見本の省略を理由に本番の保護を削らない。

## 配置を決める順番

1. この見本でボタンの階層とメモA/Bを判断する。
2. メモの編集方式を実際の記録画面で比較する。開閉による数値入力位置、文字拡大、キーボード、保存後フォーカスを確認する。
3. 合意した範囲を正本へ移す。古い「角丸原則0」と新しい適用範囲の関係を明示する。
4. `frontend/src/styles/` と必要な共通UI部品へ移し、見本も同じ実装を参照する。個別画面から色・角丸の上書きを外す。
5. ホーム/記録/設定で確認し、残る例外を#186で追跡する。カードの共通メニューは#184との境界を保つ。

採用記録には対象・決定・理由・確認した画面・関連コミットを残す。今回の案は未決。アプリの全画面変更、API/DB変更、基準の確定はこの比較作業に含まない。
