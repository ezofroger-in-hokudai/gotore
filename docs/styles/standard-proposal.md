# デザインスタンダードの検討案（#186）

2026-09-20。「デザインスタンダードをがっつり考える」という依頼の議論用資料。採用前であり、[既存基準](../design-system.md)やアプリの仕様を上書きしない。まず[現行デモ](index.html)と実画面を比較して決める。

## 目指す状態

新しい画面を作るとき、毎回色・角丸・余白・操作位置を考え直さずに済むこと。同じ役割には同じ見た目と操作を使い、例外の理由を追跡できること。

現状の基準には「角丸原則0」「メモ常時表示」があり、その後採用された角丸・メモ切替・BESTの詳細表示等との整理が必要。旧基準へ戻すことを既定にしない。

参照は現行カタログの07a397d、発表用のホーム/記録画像、目安箱PR #190の設定UI。最新main全体を監査済みとは扱わない。v2.cssの単純な宣言集計では角丸19・font-size38・padding59・gap22種類の表記がある。同値のpx/rem表記、複合指定、意図した例外も含むため、この数だけで不良や削減目標とは判断しない。

## 最新の合意（2026-09-21）

メモとトレーニング中の画面は現行を基準にする。メモA/Bとシート編集案は撤回し、既存の見た目・配置・操作から共通ルールを整理する。以下の比較候補は、それ以外の画面を検討するための資料であり、記録画面の再設計は行わない。

## 1. 最初に決める方向性

| 候補 | 何を大切にするか | 見本で比べる点 |
| --- | --- | --- |
| 現行を磨く | 赤と適度な角丸、使い慣れた操作、読みやすい記録 | ボタン/メモ/カードの角丸と密度を少数のルールに揃える |
| 硬派でコンパクト | 数値と操作を主役にする | 輪郭・区切り線、抑えた装飾、セットの見渡しやすさ |
| 楽しさ・達成感 | 仲間の存在と自分の変化を感じる | ホーム・スタンプ・結果/レポートの強調量 |

どれも既存の数値入力の操作を変更する指定ではない。ユーザーの選択と気になる箇所を確認してから見本案に落とす。

## 2. 画面を通した共通原則の案

- 次に押す場所が分かる。主操作・補助操作・削除を階層化する。
- 日常の記録は少ない操作で進める。使い慣れたホイール/増減/直接入力を維持する。
- 種目名・重量・回数・今回/前回の関係を読みやすくする。単位を省いて意味を変えない。
- コンパクトな見た目と押せる範囲を分ける。小さいスタンプでも操作領域は確保する。
- 情報のまとまりに余白を使う。同じ意味の要素を別々の箱で囲みすぎない。
- 初回・更新中・空・失敗を区別し、記録なしと読み込み失敗を混同させない。
- 記録中・同期待ち・確定を混同させない。成功通知の見た目を揃えても確定条件は各API仕様に従う。
- ライトとダークを同時に決める。黄色いメモなどの固定色も両方で確認する。

## 3. 基礎スタイル：役割と値をセットで決める

以下の数値は比較開始用の候補であり、確定値ではない。

| 分類 | 候補・決め方 |
| --- | --- |
| 色 | 背景/面/本文/補助/境界/主操作/選択/エラー/成功/メモに役割名を付ける。主操作の赤と削除の赤は文言・配置・確認で区別 |
| 文字 | 補助12、本文/ボタン14、入力16、節見出し16〜18、画面見出し20〜24。入力値や成果の大きな数値は別の役割 |
| 太さ | 通常400、強調600、主な数値/見出し700を候補に、フォントで見比べる |
| 余白 | 4/8/12/16/24/32を基本候補。画面左右16、部品内12〜16、節間24。記録画面は密度を別途検証 |
| 角丸 | 入力・ボタン・カード・シートの役割で少数に制限。現行8/10/12/14等を見比べて採用。顔画像の円・スタンプの丸みは別用途 |
| 操作領域 | 共通基準48pxを起点とし、表示上の小さいアイコンにも確保。領域同士を重ねない |
| 枠・影 | 通常は背景差と細い境界。影は浮く操作や重なりの必要な場所だけ |
| 動き | 押下・開閉・達成に用途を限定。短い遷移、動きを減らす設定、入力位置を動かさないことを確認 |

値だけでなく「この値をいつ使うか」を見本に添える。画面ごとに14pxと13pxを気分で選ぶような実装を減らす。

## 4. 部品ごとに統一する内容

### ボタン

| 種類 | 使う場面 | 比較・合意する内容 |
| --- | --- | --- |
| 主操作 | 開始、次のセット、送信、確定 | 赤の塗り、文字、角丸、高さ。画面または独立した操作領域ごとに主操作を絞る |
| 補助操作 | 次の種目、戻る、別の方法 | 枠/薄い面、主操作との幅と位置関係 |
| 文字操作 | 編集、閉じる等 | 文字だけで押せると分かる場面に限定。操作領域を確保 |
| アイコン | …、＋、メモ等 | 共通サイズ・位置・読み上げ名。絵文字とUIアイコンの用途を分ける |
| 削除 | 自分の記録・グループ等 | 通常はメニュー内、確認画面で対象と結果を明示。キャンセルを近くに置く |

全種類について通常・押下・フォーカス・無効・処理中の見本を並べる。送信中だからと画面全体を一律に無効化せず、重複や競合する操作を各機能のルールで制限する。

### メモ・トレーニング中（現行を基準にする）

ユーザー指定により、現行のメモ配色・配置・開閉・その場での編集を基準にする。数値入力・セット一覧・追加・終了操作も現行を起点とする。共通化はこれらの見た目と操作を維持して行う。

種目メモと今回の記録メモの保存対象、本人限定、下書き保持・復元などの既存仕様も維持する。現行値は[部品見本](index.html#memo)、合意の詳細は[採用事項](component-decisions.md)を参照する。

### カード・行・メニュー

- 記録カード：誰の/いつの/何の記録か → 主な実績 → 反応の順に情報を揃える。
- 設定や管理の一覧：項目名・現在値・進む印を同じ配置にする。
- 補助操作：#184の「…」へ記録全体の確認・管理をまとめる要望を踏まえる。送信者確認は記録詳細へ置く。
- 他人の記録、自分の記録、グループで可能な操作が異なっても、メニュー位置と開閉は揃える。
- 空・長い名前・多数のスタンプ・削除後・通信失敗を同じ見本で確認する。

### シート・フォーム・通知

- 小さな確認/短い編集はシート、長く読む情報は詳細画面を候補にする。採用基準を文章化する。
- 見出しと閉じるの位置、本文余白、確定操作の位置、キーボード表示時のスクロールを揃える。
- 入力ラベルを欄の外へ置き、placeholderだけに役割を持たせない。
- エラーは入力/操作の近くに、何をすればよいか分かる文言で示す。
- 成功表示は控えめにし、トレーニング終了や自己ベストの達成表現とは区別する。

## 5. 画面の型を分ける

| 型 | 対象 | 密度・配置の考え方 |
| --- | --- | --- |
| 記録する | トレーニング中 | セットを見渡し、数値入力と保存にすぐ届く。通常時の操作スクロールを減らす |
| 一覧から選ぶ | グループ一覧、種目一覧 | 見出し/検索・絞り込み/一覧/追加操作。選択対象と補助操作を区別 |
| 読む・振り返る | ホーム、履歴、レポート | 最初に要点、詳しい内容は順に読む。適度な縦スクロールを許容する案 |
| 設定・管理 | 設定、グループ管理 | 項目を行で揃え、変更を開いた先で完結させる |

旧基準の「通常操作は1画面」の適用範囲を確認する。レポートまで詰め込むことや、記録画面を情報量の少ない大きなカードへ置き換えることを自動的に採用しない。

## 6. デモで決める順番

1. ボタン：同じラベルで種類・サイズ・状態を並べる。
2. メモ・記録中：現行の配置・操作を基準に、共通化で差が出ないことを確認。
3. 記録カード：本人/仲間、スタンプ、共通…の配置を比較。
4. 設定/目安箱：行、シート、入力、送信/失敗を確認。
5. ホーム/記録/履歴で並べて、アプリ全体として一貫するか確認。

各段階で「現行」「提案」「採用」を区別し、採用後は古い候補を実装の参照先に残さない。大量の見た目を一度に選ぶ負担を避ける。

## 7. 実装時にばらつきを防ぐ仕組み

現行docs/styles/current/は比較用CSSスナップショット。アプリが参照する共通スタイルへ切り替える段階では、次の構成を候補にする。

```text
frontend/src/styles/
  tokens.css       色・文字・余白・角丸・テーマ
  components.css   共通部品の基本形と状態
frontend/src/components/ui/
  button.tsx       役割/状態で指定するボタン
  field.tsx        ラベル・説明・エラーの共通配置
  ...              実際に複数画面で使う部品だけ追加
```

- デモとアプリが同じスタイル/部品を参照する。見本だけを別CSSで完成させて放置しない。
- 画面のCSSは配置を担当し、共通部品の色・文字・角丸を後から上書きしない。
- 共通部品を変えるときは状態一覧と代表画面を確認する。
- 例外は用途・理由・適用箇所を記録する。同じ例外が増えたら部品の種類として再検討する。
- AGENTS.md/CONTRIBUTING.md/PRテンプレートから基準とデモを参照する。
- 新UIライブラリや網羅的な部品開発は前提にせず、今使うものから共通化する。

## 8. 採用・完了の確認

- 320/390/430px、長い日本語、文字拡大、キーボード、ライト/ダーク。
- 押下/フォーカス/無効/読み込み/空/失敗/再試行。
- ボタンが見える、文字が欠けない、隣の操作を誤って押さない。
- 私的メモ/共有先/未同期/取り消せない削除など必要な意味が伝わる。
- 必要に応じコントラストを計算し、見た目だけで読みやすさを判定しない。
- 既存の保存・共有・復元の仕様を維持する。
- ユーザーが操作する代表画面で採用を確認したうえで、デザイン基準の正本を更新する。

メモ・記録中は現行を基準にすることで合意済み。次は他の画面へ展開する共通値と部品を整理する。
