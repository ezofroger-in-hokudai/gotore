# 画面文言の削減案（2026-09-13）

ユーザーの「二回無駄に書いているもの、ヒートマップの色の指標バーなどを減らし、できる限り提案してほしい」という依頼に対する棚卸し。**ユーザーの了承を受け、#140でA01〜A15・B01〜B09を実装する。B10〜B12・C01〜C10は比較・条件整理の候補として残す。**

確認対象は、承認済みの部位8分類を含む [PR #139](https://github.com/ezofroger-in-hokudai/gotore/pull/139) のコミット `4c2ba7a9e5ee5c6965778363a10353f38d0f1892`。文書ブランチの基点は main `aa793f5`。ソースとCSSの表示条件を確認した棚卸しであり、今回すべての状態をブラウザで実機確認したわけではない。

[現行の文言方針](ui-copy.md)と[デザインルール](design-system.md)を参照した。現行方針の「カレンダーの凡例を保持」は、今回の削除希望を反映して実装時に更新する。他の保持対象の変更は下表の条件とともに検討する。

## まず削除を勧めるもの（15件）

| ID | 画面・現在の表示 | 提案・理由 |
| --- | --- | --- |
| A01 | カレンダー：灰色の「未記録」、色の帯、0kg〜最大値の目盛り | 凡例一式を削除。日付マスの色と数値を主役にする。月内最大値に対する相対色であることはガイドへ移す |

## 見た目を比べて決めたい案（10件）

| ID | 候補 | 提案・判断する点 |

| C02 | 未記録日の「—」 | 日付と灰色だけにする。読み上げでは記録なしと分かる状態を維持。0kgの記録とは区別する |
| C03 | 履歴詳細の「セット詳細」 | 常時展開する個人詳細では開閉行をなくして直接表示する。閉じる操作を残したいか、画面で比較する |

| C10 | プロフィール画像シートの上の「閉じる」と下の「戻る」 | 同じ閉じる操作なら1つにする。スマホで片手操作しやすい位置を確認して決める |

## 消さないもの

- 共有先、メモは本人のみ、ランキングの共有記録のみという集計範囲。
- 端末保存・未送信・同期失敗・競合と再試行の操作。保存完了と送信待ちを混同させない。
- 重量・回数・セット数・総負荷・1RMの区別と単位、前回／今回、記録の投稿者。
- 削除・退出・除外の対象と確認。取得失敗を「記録なし」に置き換えない。
- ホーム・履歴などの画面タイトルとナビゲーション。現在地の表示と移動操作は役割が違う。
- 目に見える説明を削った際の入力ラベル・読み上げ名・タップ領域。

CSSで非表示の履歴詳細の投稿者・日付・セット数の行、設定シート内の内側の「設定」は、現在見えている重複として数えていない。停止中のスコア画面の文言も対象外。すでに削除済みの「総負荷カレンダー」、選択部位の再掲、ランキングの重複見出しは候補に含めていない。

## 実装する順序の提案

1. A01〜A15とB01〜B09を小さな画面整理として実装し、変更前後を比較する。
2. B10〜B12とC05は、選択指標・初回読み込み・キャッシュ・未送信・失敗を含む表示条件を検証して進める。
3. Cの残りは画面を比較して採用範囲を決める。すべてを削除する前提にはしない。

アプリ実装時は文言方針を更新し、320/390/430pxで通常・空・読み込み・失敗を確認する。共有コンポーネントはホーム・個人詳細・共有詳細で確認し、削除した見出しを読み上げ名として保持する。記録・共有の動作に触れる場合は既存E2Eも実行する。今回の文書作成ではアプリテストを追加・実行しない。
