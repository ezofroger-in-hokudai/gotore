# グループ切り替えスライドの調査

2026-09-14のユーザー依頼による調査。関連: #118、[グループ表示順の仕様](gotore-v2-spec.md#グループ表示順118)。以下は調査時点の記録。ユーザーの修正依頼を受けた対応は末尾に追記する。

## 確認環境

- 対象コード: main `f860af6`。ローカルの既存ビルド `d5795c3` で計測した。`community.tsx`、`use-group-card-drag.ts` はmainと同一。CSS差分は履歴画面のみで、カルーセルには差分がない。
- Playwright Chromium、CDPの実タッチ入力イベント、画面幅320/390/430px。認証・グループAPIは既存の `mockTraining` と同様のモックを使用し、3グループを表示。
- 実機Safari・Android・PWA、およびegotore.comの公開中ビルドは未確認。ユーザーの端末と具体的な症状との一致は未確定。

## 1. 指を離すと移動位置が一度戻る

再現手順: 先頭のカードを左へ60px動かし、長押しにならないうちに指を離す。次のカードへ進むが、その開始位置が指を離した位置から戻る。

documentのpointerupをcapture/bubbleで観測し、Reactのハンドラー前後で座標を取得した。

| 画面幅 | 離す直前のscrollLeft | ハンドラー後 | 移動完了後 |
| --- | --- | --- | --- |
| 320px | 60 | 0 | 274 |
| 390px | 60 | 0 | 336 |
| 430px | 60 | 0 | 376 |

原因は [use-group-card-drag.ts](../frontend/src/features/v2/use-group-card-drag.ts) の `finish` が `stop()` を先に呼ぶこと。`stop()` は無効化していた `scrollSnapType` をCSSの `x mandatory` へ戻すため、現在位置が先頭へ吸着する。その後で `scrollTo({ behavior: "smooth" })` が次のカードへの移動を開始する。3幅すべてで同じ座標の巻き戻りを確認した。

修正方針: ジェスチャーの後片付けとスナップの復帰タイミングを分け、指を離した位置から目標位置まで移動する。位置の連続性を確認する回帰テストを先に追加する。

## 2. 連続スワイプの結果が操作間隔で変わる

再現手順: 390px幅の先頭カードで左へ60pxのスワイプを2回行う。いずれも長押しなし。

| 1回目を離してから次の操作までの待機 | 最終的なカード |
| --- | --- |
| 0ms / 50ms | 2枚目（1回分） |
| 150ms / 350ms / 600ms | 3枚目（2回分） |

原因は同フックが次のpointerdown時点の `scrollLeft` を記録し、`finish` で `Math.round(current.scroll / current.pitch)` を起点にすること。アニメーションがまだ先頭寄りなら2回目も先頭からの操作として計算される。目標カードと移動途中の座標を別々に保持する仕組みがない。

修正方針: アニメーション中の目標カードと現在位置を区別して次のジェスチャーへ引き継ぐ。連続した同方向・逆方向の操作を回帰テストに含め、長押し並べ替えと通常タップの判定を維持する。

## その他の観測と検証範囲

- 30pxの短い移動は元のカードに戻り、60pxと240pxの単発スワイプは次へ進んだ。コード上は40px超で次へ進める補正があり、速度の判定はない。これは今回確認した閾値であり、変更する仕様の提案ではない。
- スワイプ中も `community.tsx` のonScrollが中央を超えると選択を更新する。240px移動中にpointercancelを送った場合、開始時の先頭ではなく更新後の2枚目へ揃った。長押しのキャンセル仕様と通常スワイプのキャンセルは区別して扱う必要がある。
- ゆっくり120px動かした通常スワイプでは、長押し並べ替えに誤判定されず2枚目へ移動した。
- 一時的な観測用テストは、操作間隔・方向・キャンセル・遅いスワイプの1件と、離す前後の座標を取得する3幅の3件を実行。計測完了は修正済みを意味しない。
- 既存の `group-order.spec.ts` 全8件が成功（20.4秒）。長押し・順序保存・本人分離・保存失敗・キャンセルを確認した。
- 既存のタッチテストは240pxのスワイプ後に最終選択と順序を確認する。離した瞬間の座標と連続スワイプの操作間隔は検証していないため、今回の問題を検出できない。

次の作業は上記2点の修正と回帰テスト、既存の並べ替え・詳細遷移・グループ表示内容の検証。実機での操作感は修正後も別途確認する。


## 修正対応

調査後にユーザーから修正依頼を受けた。

- 指を離した位置から220msで終点へ補間し、到着後にスナップを戻す。ブラウザのスナップとsmooth scrollを同時に開始していた競合をなくした。
- 移動中の目標カードを保持し、次のスワイプはそのカードを起点にする。新しいポインター操作ではアニメーションを停止し、その時点の位置から指に追従する。
- ドット、画面離脱、所属変更、キャンセルでは移動を停止する。動きを減らす設定では即時に切り替える。通常タップ・長押しの並べ替え・保存方法は維持する。
- `group-order.spec.ts` に3幅の離す前後の位置、連続/逆方向/短いスワイプ、ドット/画面遷移の割込、動きを減らす設定の6件を追加。修正前に跳ね戻り2件と連続操作1件の失敗を確認し、修正後は既存8件と合わせて14件成功（35.3秒）。標準チェックもbackend240件/frontend75件、lint・型・buildが成功。

全E2E・提出状況の最終結果は [progress.md](../progress.md) に記録する。実機Safari/Android/PWAでの操作感と本番反映は別途確認する。
