# GOTORE v2 実装仕様

2026-09-09のユーザー回答と整合性レビューの推奨案を反映する。新UIはdocs/gotore_v2の確定版を基準とし、業務ルールは本書を優先する。既存APIの互換動作と過去の共有範囲は保持する。

## 合意と適用範囲

- 現行Next.js/FastAPI/Supabaseで実装する。新しいトレーニングは開始時点で所属する全グループへ共有する。閲覧中のグループは共有先に影響しない。開始前と記録画面に共有範囲を短く表示する。
- 既存の非公開・単一グループの記録は移行で共有範囲を広げない。開始後に参加したグループには次のトレーニングから共有する。退出・除外時はその所属への共有を解除し、再参加で復活させない。
- 終了ボタンで明示的に終了する。ホーム・別タブ・再読み込み・アプリを閉じる操作では終了しない。サーバーに進行中セッションを1人1件保存し、同じアカウントで復元する。未送信の入力はユーザー別ブラウザ下書きとして保持する。
- LIVEを追加する。未終了かつ最終生存確認が5分以内の人を数え、表示中は30秒ごとに生存確認。切断してもセッション・記録は削除せず、復帰時に継続する。非表示中は通信停止。期限切れを完了とは表示しない。
- TODAYはJSTの当日に開始・セット保存・生存確認した現在のメンバーを重複なく数える。終了しても残す。旧記録は記録日を使う。人数と名簿は同じ共有条件で取得する。
- 招待コードは現行12桁。必要な縦スクロールを許容し、過大な余白や重複表示を避ける。Push通知は後続の[Issue #21](https://github.com/ezofroger-in-hokudai/gotore/issues/21)で追跡し、未接続のオン設定は出さない。

## 記録・集計

- セットは送信待ちデータを端末へ永続化した直後に画面へ追加し、次セットの入力を可能にする。サーバー保存は順序付きでバックグラウンド実行し、成功時に共有表示を更新する。入力途中は共有しない。1セッション1ID、revisionで更新の競合を検出し、同じ要求の再送で重複させない。終了も期待revisionと照合する。
- 0セットの進行中セッションを許容する。履歴一覧とセット数集計は1セット以上の記録を対象とする。終了済み空セッションは履歴に表示しない。
- 保存済み行の編集は対象の種目・セット位置と期待revisionを使い、新規追加と分離する。キャンセルは保存値を変更しない。「元に戻す」は直前の保存（追加・訂正）を、次の更新前に取り消す。
- 種目は本人と前後空白除去後の名前の完全一致で識別する。同名行は保存順に全セットを参照する。種目候補の削除・再追加で履歴や継続メモを消さない。
- 前回はその種目を含む直近の過去セッション。現在のセッションを除外し、日付・開始時刻（旧記録は保存日時）・IDで順序を確定する。50件の表示ページとは独立して全履歴を対象にする。
- 推定1RMは正の重量で1回なら実重量、2〜10回は重量×(1+回数/30)、小数1桁で四捨五入。0kg・11回以上は「—」。重量0〜1000kg/小数1桁、回数1〜1000の保存制約は維持する。全画面が同じ規則を用いる。
- 最高重量・最高RMは全保存済み実績から独立に算出する。丸め後の同値は更新しない。初回は基準値の登録。保存前は候補表示、追加保存成功後だけ更新演出。訂正・削除・取消では最新内容から再計算する。
- グループのBESTラベルは直近の追加保存で本人の最高値を更新し、現在も最高値である場合だけ表示する。同値・初回・訂正・取消では新しいBESTを付けない。私的履歴そのものやメモは共有DTOへ含めない。
- 継続種目メモは本人限定0〜1000文字・改行可、明示保存、revisionによる競合と再送を検証。記録単位メモは既存APIを保持し、「セッションメモ」と区別する。
- 旧記録の所要時間は未計測。新セッションは開始・終了の差を使う。終了後の履歴編集で開始・終了時刻を変更しない。

## UIと既存機能

- 2026-09-09追加依頼のLIVEの赤丸・ラベル・新着強調と、設定からのプロフィール画像変更は[ライブ表示とプロフィール画像](live-presence-avatars.md)に従う。LIVEの業務条件は維持し、表示側でも期限と通信状態を確認する。

- 下部ナビはホーム・記録・履歴・設定。ホームのカード選択は画面内状態で保持し、カード切替で戻る履歴を増やさない。詳細/一覧/招待は対象グループを保持する。一覧選択・作成・招待参加の遷移時は遷移先のIDを履歴へ記録し、ブラウザの戻る・進むでも同じ対象を復元する（#71）。
- 重量・回数は指の移動中に連続更新するホイールと数値タップによる直接入力。2.5kg以外の既存値を丸めない。通常の320/390/430px幅・720px以上の高さでは、入力・保存・メモ・終了をページスクロールなしで操作できる構成にする。比較セットは全行を縦に並べ、一覧内をスクロールして確認する。入力・「次のセットへ」「次の種目へ」は一覧の下へ押し出されない位置に置く（#62への追加回答）。メモは枠を強調せず本文として表示し、タッチで編集する。種目メモの直下には前回のメモの本文がある場合だけ表示し、説明ラベルや空欄は出さない。今回のメモの入力導線も短い「メモ」で維持する。文字拡大・キーボード・長文には必要なスクロールを残す。
- 直接入力の重量欄でEnterを押すと、値が有効な場合だけ回数欄へフォーカスを移し、セットは保存しない。新規・編集とも同じ動作とし、IME変換確定・長押しのEnterでは移動・保存しない（#69）。
- 2026-09-11の追加回答により、回数欄の通常Enterは「次のセットへ」と同じ送信操作とする。編集中は「変更を保存」と同じく対象セットを更新する。無効値・IME変換確定・長押しでは保存せず、送信キュー・競合・二重送信の制御を共用する（#69）。このv2の採用動作は旧版daily-improvements.mdの「Enterで確定送信しない」に優先する。
- 重量と回数の入力欄の上に増やす矢印（▴）、下に減らす矢印（▾）だけを表示する。増減ボタンには隣接値を表示せず、数値は中央の入力欄に集約する。ボタンは重量±1kg・回数±1回で調整する（#88）。重量の小数1桁を保持し、下限0kg／1回と上限1000を超えない。ボタン操作だけでは保存しない。スワイプの刻み（重量2.5kg／回数1回）と直接入力は維持する。

- 送信待ちはユーザー別に端末へ保持し、通信失敗・再起動後も復元・再送する。画面では端末への追加とサーバー同期完了を区別する。編集・取消も同じ順序で送り、共有とBESTの確定はサーバー応答を待つ。終了は未送信分の反映を確認してから行う。
- 初回の進行中セッション取得に失敗した場合は、オンライン復帰・画面の表示復帰・表示中の5秒ごとの再試行で再取得する。同時に発生した復元要求はまとめ、サーバー確認前に新規セッションを開始しない。未送信・競合・破損した端末データは自動破棄しない（#73）。
- 別端末の更新と競合したときは未送信データを保持して送信を停止し、確認なしに上書き・破棄しない。端末への永続化に失敗した場合は追加成功と扱わない。
- 招待はコード入力→名前と人数の確認→参加。確認では所属を変えず、参加時に再検証する。未実装の招待リンクの案内は削る。
- グループ名変更・退出・メンバー除外・招待再発行、ログイン/ログアウト、ガイド、本人記録の編集/削除/コピー/私的メモ、種目候補の追加削除を保持する。
- テーマは端末連動/ライト/ダークを端末に保存。振動は対応APIがある端末だけ操作に反映する。読み込み・空・失敗を区別し、取得失敗を0人/0kgと表示しない。

## 検証とリリース

先行テストで多グループ共有・再開・再送・同時更新・終了・退出/再参加・日付境界・BEST訂正・私的メモを確認する。make check、専用_test DBで統合テスト、ローカルSupabaseでmake test-e2e、320/390/430pxの画像と文字拡大を検証する。実機の操作感は別途実機で確認し、自動テストで代替したと記載しない。

追加migrationをAPIより先に適用する。本番への反映・マージは今回の実装と別操作。#8・#30の担当を勝手に変更せず、開始時の公開中PRは0件であることを確認した。元資料と開始時からの未コミット変更は一括コミットしない。

記録画面の表示名は「1RM」「次のセットへ」「トレーニング終了」とする。「次のセットへ」は現在のセットを端末へ追加して次の入力へ進む操作で、送信待ちキュー・バックグラウンド同期の規則は変えない。メモの公開範囲・保存先は変えず、読み上げ用の識別名は保持する。

PR #63の使用後フィードバックでは、追加したセット番号・送信状態と次に記録する番号を示す。タッチ後にホバー色を残さない。「次の種目へ」は主操作の横に幅を抑えた枠付きボタン、「トレーニング終了」は画面上部の同じ位置に枠付きボタンとして置く。「新しい種目を追加」は種目リストの末尾に置く。最高記録の更新候補と確定を区別し、追加保存が確定したBESTは赤色と炎で強調する。開始・終了は処理中を明示し、サーバー応答前に成功表示しない。

PR #64への追加指定では「次の種目へ」を左、「次のセットへ」を右に置く。比較一覧の「重量×回数 / RM」の説明行を取り除き、各セットのRMは数値の横に置く。BESTの説明文言は視覚表示から除き、確定した更新は赤色と炎、入力中の候補は赤色だけで示す。読み上げ用の説明は残す。今回のトレーニング一覧では、他の保存済み記録を基準にセット順で最高重量・RMを更新し、現在の最高値を保つセットを赤色・炎で強調する。初回・同値だけでは更新扱いにせず、未送信分は強調しない。訂正・取消後は保存済み内容から再計算し、他人の履歴を返さない。

## #61・#62の操作改善

- 記録ホームに進行中トレーニングの全種目・セットを表示し、種目選択に戻って同じセッションへ追加できる。日付をまたぐ場合もセッションを分割しない。未保存入力を別種目で置き換える際は確認する。同じ種目へ戻るだけなら入力・編集状態を保持する。
- 種目選択から「新しい種目を追加」で本人用種目リストの登録フォームを直接開く。既存の1〜60文字・削除後の履歴保持を維持する。
- 開始APIを待つ間も種目を選択できる。開始成功前はセット保存を有効にせず、失敗時は選択を保持して同じ開始IDで再試行する。
- 読み込み中もカード・セット比較・メモ・カレンダーの領域を用意する。未取得の人数やセット数を0と表示しない。再訪のメモリ保持と更新失敗時の扱いは[読み込み仕様](loading-performance.md)に従う。

## ホームから共有記録の詳細を開く（#89）

2026-09-11のユーザー回答により、タップしたワークアウト1件の全種目・全セットを表示する。同日の別ワークアウトは含めない。

- ホームとグループの最新記録のセット部分から詳細シートを開く。記録日・表示名・種目・セット順・重量・回数・推定1RMを表示する。記録日は更新日時から推測せず、記録のperformed_onを使う。
- `GET /api/groups/{group_id}/workouts/{workout_id}`で、閲覧者の現在の所属と対象記録の共有先を毎回確認する。未認証401、未所属・不明・削除済み・そのグループへ未共有は404。
- 私的メモ・種目メモや他グループの共有先IDを応答へ含めない。閲覧専用で、本人の記録でもこのシートには編集・削除・コピー・メモ操作を出さない。
- 開いたときだけ詳細を取得する。シート表示中は既存の5秒周期で確認し、非表示タブでは停止する。取得失敗時には前の内容を隠し、再試行を表示する。閉じる・ブラウザの戻るでホーム／グループの選択状態を保つ。閲覧だけで保存・共有しない。
- DB migrationは追加せず、既存の共有範囲を維持する。

[詳細の確認画像](images/shared-workout-detail.png)は、Linux/Chromium・390×844の架空記録。320/390/430pxで横方向のはみ出しがなく、閉じる操作を表示できることを確認する。
