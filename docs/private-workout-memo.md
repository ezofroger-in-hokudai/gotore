# 本人だけの記録メモ（#43・#22）

画面文言は2026-09-08の[簡略化方針](ui-copy.md)を優先する。説明は初回ガイドに集約し、以下の業務ルールを維持する。

2026-09-08のユーザー指示に基づき、発表資料の本人メモを個人の振り返りとして採用する。他人からのコメント・自己採点・通知は#22の後続。

- 「自分の記録」の本人の記録から「メモ」を開く。初回ガイドでグループには共有されないと明示する。
- 保存済み記録に対して0〜1000文字・改行可のプレーンテキストを保持する。空欄を保存すると内容を消去する。HTMLやMarkdownを実行しない。
- 専用の `GET /api/workouts/{id}/memo` と `PUT /api/workouts/{id}/memo` を使う。本人限定で、他人・不明記録404、未認証401。グループのオーナーにも閲覧・更新権限はない。
- 記録一覧のDTOにはメモを追加しない。必要時のみ専用APIから取得し、グループ共有APIへ本文・有無を含めない。
- 応答はcontentとrevision。未作成は空文字・revision=0。PUTはcontent・expected_revisionだけを受け付け、変更でrevisionを1増やす。競合409、直前の同じ変更の再送は成功応答のみ返す。
- 空欄化後も版番号だけ維持し、古い要求で本文を復活させない。元記録の削除時は外部キーのCASCADEでメモも削除する。#19の共有解除では元記録が残るため本人メモも残る。
- 通信失敗・競合では入力を保持する。「保存済みを読み直す」は入力の破棄を明示し、確認後に最新の内容を読み込める。v2では未保存メモの本文と編集元revisionを、ユーザー・対象記録ごとにlocalStorageへ保持する（#70）。閉じる・終了・再読み込み後も本人の履歴から復元し、保存成功または確認した読み直しの成功後に下書きを消す。記録の削除成功後は対応する下書きも削除する。通信失敗・競合・読み直し失敗・削除失敗では保持する。端末保存が使えない場合は警告し、保存済みと誤表示しない。旧初版の「localStorageには保存しない」はv2では適用しない。
- migrationで専用テーブルとRLS・外部キーを追加する。既存データの変更は不要。APIより先にmigrationを適用する。
- テストで所有権・共有への非表示・1000文字境界・HTML文字列・競合・再送・空欄化・元記録削除と共有解除を確認する。

## 種目メモとの区別

記録入力中に参照・記入する種目メモは、[記録画面の追加要件](design-system.md#record-input-context)（#56・#22）で扱う。v2では種目メモも実装済みで、ワークアウト単位の今回・前回メモとは別対象で保持する。前回メモの下書きはその元記録の本人履歴から復元できる。種目名の下書きと記録IDの下書きを混同しない。
