# 種目の部位保存・選択

2026-09-13の依頼。既存の[本人用種目リスト](exercise-options.md)へ部位を追加する。画面を含めたA案の承認に基づき、主な部位1つ＋任意の補助部位で実装する。

## 操作と範囲

- 部位は胸/chest・背中/back・脚/legs・腕/arms・肩/shoulders・腹筋/abs・お尻/glutes・その他/otherの8分類に固定する。保存値は言語に依存しないコード。2026-09-13の固定8分類案への承認で全身/full_body・未設定/nullをその他へ統一する。
- 種目の追加時と既存候補の編集時に主な部位1つ、補助部位0〜7個を指定する。重複、主補の重複、不明コードを拒否する。本人が目的に合わせて変更できる分類であり、負荷の部位別配分率ではない。
- 種目選択は「すべて」と8部位と種目名検索の積集合。主/補のどちらでも部位に一致させる。絞り込みは取得済み一覧で行い追加通信しない。入力画面にも部位を表示する。
- 旧候補・削除済み候補の下書き・今回使用済み種目を失わない。分類なしはその他として選べる。追加/編集失敗は入力と保存済み一覧を保持し再試行できる。
- 分類は本人のリストのみ。既存記録JSONの名前/重量/回数や共有範囲は変更せず、友達の分類を閲覧者の分類で上書きしない。部位別集計は後続で主補の扱いを定義する。

## 標準候補と移行

初回8候補と、migration時点で同名の既存候補に編集可能な初期分類を設定する。独自名を推測で分類しない。全削除した候補を再作成しない。

| 種目 | 主な部位 | 補助部位 |
| --- | --- | --- |
| ベンチプレス | 胸 | 腕・肩 |
| スクワット | 脚 | お尻 |
| デッドリフト | お尻 | 背中・脚 |
| ペックフライ | 胸 | 肩 |
| ラットプルダウン | 背中 | 腕 |
| ショルダープレス | 肩 | 腕 |
| 懸垂 | 背中 | 腕 |
| 腕立て伏せ | 胸 | 腕・肩 |

大きな部位の整理は[ACEの部位分類](https://www.acefitness.org/resources/everyone/exercise-library/)を参考にし、脚はまとめた。デッドリフトは[NASMの対象筋](https://www.nasm.org/resource-center/exercise-library/barbell-deadlift)を参考に、アプリで探すための初期分類を上表へ簡略化する。主な部位を1つにするのはアプリの分類方針であり、複合種目が1部位だけに作用する意味ではない。

## APIと整合性

- GET /api/exercise-options: 既存のid/nameにprimary_body_part、secondary_body_parts、revisionを追加。分類取得の別通信は不要。
- POST /api/exercise-options: nameに任意の分類を付ける。省略時はその他。旧クライアントのnull/full_bodyもその他に正規化する。既存の同名追加・再送は保存済み候補を返し、分類を勝手に上書きしない。
- PATCH /api/exercise-options/{id}: expected_revisionと分類を受け更新する。同じ更新の再送は成功し、競合は409。分類編集では種目名を変更しない。
- 所有者は認証済みユーザーから決める。他人/不明IDは404、入力不正422、基盤障害503。既存のRLS/認証/no-storeを維持。
- gotore_exercise_optionsの主部位をNOT NULL・既定otherとし、補助も8コードに限定する。候補/履歴を削除しない。既存値を読み書き時に正規化できるAPIを先に更新し、migration、Webの順に反映する。

## 採用画面（A案）

- 検索の下に折り返す部位ボタンを置き、一覧に主部位と補助部位を表示する。切り替えは取得済み候補の絞り込みだけで完了する。
- 今回のトレーニングはコンパクトにまとめ、種目をタップして記録へ戻れる。セットの詳細は展開して確認する。
- 種目一覧から追加・部位編集を行う。補助部位は必要なときに開く。保存の失敗では入力を保持し、競合時は明示的に最新の分類を読み直せる。
- 履歴の種目選択も主部位ごとにまとめる。既存の種目名とセットの保存形式は維持する。


## 固定8分類への移行

`20260913080000_fixed_body_parts.sql` で全身・未設定をその他へ統一し、補助の全身もその他へ変換する。変換で主補が一致したり補助が重複した場合は1度だけ残し、表示順（胸・背中・脚・腕・肩・腹筋・お尻・その他）に整える。分類が変わった候補だけrevisionを1増やし、古い編集による上書きを防ぐ。ID・名前・履歴本文・所有者を保持し、削除済みの候補を復元しない。

APIは旧null/full_body入力と応答を正規化し、画面も旧キャッシュをその他として表示する。未知のコード、明示的な重複・主補一致は引き続き拒否する。カレンダーは削除済みの種目もその他に集計し、同じ記録の旧分類が合流しても記録件数を重複させない。部位別ランキング自体は今回追加せず、分類コードを今後の共通基準にする。

## 開始前の管理と保存結果の即時反映（#148）

2026-09-14、全体候補のIssue化・継続実装の承認に基づく追加。設定の「種目」から本人の一覧を開き、セッションを開始せずに追加・分類変更・削除できる。管理一覧も名前検索と8部位（主/補一致）で絞る。取得済みデータを使い、絞り込みで通信しない。編集から戻っても検索と部位を保持する。

通常は一覧を先に表示し、`種目を追加` を押すと設定シート内の独立した追加画面を開く。画面は見出し、種目名、主な部位、任意の補助部位、赤い追加、白いキャンセルの順にし、一覧の検索・絞り込み・行操作を混ぜない。空一覧では追加画面から開始する。削除確認は対象の行に置き、本人の履歴が残ることを明示する。取得失敗は空一覧と区別し、読み直しで復帰する。

設定・記録・本人履歴の編集は同じ候補データを共用する。POST/PATCHが返す保存済み候補とDELETE成功を即時反映し、その後に背景で一覧を確認する。先に開始した古いGETで確定内容を巻き戻さない。再GETが失敗しても成功結果を表示する一方、認証/権限喪失では既存のデータ消去規則を守る。分類変更で履歴/分析の再確認を促し、表示済み内容を保持する。

先読みと成功後の即時反映は画面側の最適化であり、サーバー成功前に保存済みとは扱わない。本人限定・revision照合・API/DB・過去の種目名と記録本文を維持する。新しい永続ストレージ、名前の変更/統合、複数種目の一括更新、並べ替えは今回追加しない。
