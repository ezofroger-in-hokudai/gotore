# 本人記録の下書き再利用（#41・#17）

画面文言は2026-09-08の[簡略化方針](ui-copy.md)を優先する。説明は初回ガイドに集約し、以下の業務ルールを維持する。

2026-09-08の自律実装指示に基づき、#17をまず実績1件から入力を始める単位に分割した。

- 「自分の記録」で本人の保存済み記録に「この内容でもう一度」を表示する。共有一覧や他人の記録には表示しない。
- 必ず確認を挟み、既存の新規下書きがある場合は置き換わると明示する。キャンセルでは保存済み記録・下書きに触れない。
- 確認後、種目と全セットの重量・回数を文字入力へコピーする。記録IDと入力行キーを新規生成し、日付はJSTの今日、共有先は「自分だけ」を初期値にする。
- 元の日付を案内し、今日の実績に合わせて修正してから保存する。コピーだけでAPIへ保存しない。既存の入力制約と共有範囲確認を適用する。
- 生成した内容は通常の新規下書きとして保持する。保存前に戻る・再読み込みしても復元できる。ストレージ失敗は既存の下書き保持不可メッセージで案内し、入力操作を継続する。
- 本人履歴APIをそのまま使い、DB・API・migration・環境変数は変更しない。コピー元を保存中に編集・削除されても、取得時の内容を新しい入力として見直すため、元の実績へ書き戻さない。
- 名前付きプリセット、BEST、目標、種目同定は#17の後続。本人用種目候補#28とは別の入力補助。
