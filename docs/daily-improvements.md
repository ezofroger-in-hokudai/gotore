# 日常操作の改善 — 2026-09-07合意

初版に追加する範囲。#4・#5・#7のうち以下を会話で承認済み。未決の機能をまとめて採用しない。

## 記録入力（#5）

- 重量欄でEnterを押すと同じセットの回数欄へ移動する。
- 回数欄でEnterを押すと次のセットの重量欄へ移動する。最後のセットなら追加し、重量・回数とも空にする。重量は直前値を候補表示し、空欄のままEnterを押したときだけ採用する。直接入力した値は優先し、保存時に空欄を補完しない（ユーザーの追加指定）。
- 不正な数値では移動・追加しない。IME変換中・キーの長押しには反応しない。Enterで記録を確定送信しない。
- 最大30セット・20種目、数値制約、下書き、共有先の明示は維持する。追加ボタンも残し、タッチだけで操作できる。
- 入力密度は上げるが、セット数にかかわらず全項目を一画面に押し込まない。横スクロールなしで操作する。

## 表示名設定（#4の一部）

- 設定画面で本人の表示名のみ変更できる。前後空白を除き1〜20文字。
- Supabase Authのuser_metadata.display_nameを正とする既存ルールを維持する。成功後にAPIのプロフィール同期を行い、メンバー一覧と過去の共有記録にも新しい表示名を使う。
- Auth更新とDB同期は別通信であり、同期失敗時にはその状態を明示して再試行できる。メール・パスワード・他人の情報は編集しない。
- 同期はPOST /api/me/profileで行い、サーバーがAuthで再検証した本人情報だけを保存する。リクエスト本文のIDや表示名は使わない。表示名の更新方法は [Supabase updateUser](https://supabase.com/docs/reference/javascript/auth-updateuser) に従う（2026-09-07確認）。

## グループ名変更（#7の一部）

- オーナーがグループ名だけ変更できる。前後空白を除き1〜40文字。所属しているだけのメンバーには変更権限を与えない。
- PATCH /api/groups/{id} にnameのみ送信する。オーナー以外・存在しないグループは404、入力不正は422。条件付きUPDATEで権限確認と変更を同時に行う。
- グループID・招待コード・メンバー・過去記録は変えない。同じ名前の再送は安全。並行した名称変更は最後にDBへ適用された値を使う。
- メンバー削除・退出・オーナー変更は後続の仕様合意が必要。
- ホーム・グループ画面の所属一覧も5秒ごとに更新し、他端末の名称変更を反映する。非表示中は停止する。メンバー詳細はグループ画面でのみ取得する。
