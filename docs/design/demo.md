# ログイン不要の操作デモ

## 採用する構成

2026-10-01のユーザー依頼: 同じドメイン、ログイン不要、本物と全く同じ画面、グループ名 **ezofrogs**。大量スタンプと開始カットインを何度も体験できる。アプリを閉じた後の通知は含めない。

- `/demo` は通常のWorkspace、記録、履歴、グループ、設定と通知部品を利用する。独立HTMLで画面を複製しない。通知と採用済みリング時計の実装を基準とする。
- 本番のログイン/DB/APIへ接続せず、デモ用通信を端末内の架空データへ差し替える。実アプリの認証・権限を緩めない。未対応のデモ操作を本番へ転送しない。
- ezofrogsの架空の仲間12人と本人、本人の過去14件と仲間の今日の記録を用意。実ユーザーのデータを読まない。
- ヘッダー右側に「デモ」を追加。通常ヘッダーが隠れる記録中/履歴でも同じ位置から開けるよう、デモ専用の固定入口として置く。共通シートに個別/連続/20件スタンプ、1人/8人開始、初期化、実際のアプリへの入口を置く。通常の画面・ナビゲーションを変えない。
- 開いている間はボタン操作なしで自動受信。初回スタンプは4秒後、その後8〜15秒ごとに8〜20件。開始カットインは初回12秒後、その後25〜40秒ごとに1〜4人。間隔と件数はランダム。タブ非表示・退出・閉じた後は停止し、非表示中の通知を溜めない。再表示時は初回の間隔から再開する（ユーザーの追加指定）。手動再生も残す。
- 受信は実際の通知キュー・表示時間・集約・閉じ方・表示タイミングに従う。記録中の開始は初期設定ではホーム復帰まで保留。設定から即時/保存後へ切替可能。
- 初回の説明ガイドは自動で出さず、設定から再表示できる。デモのログアウトはデモ初期化として扱う。
- デモ保存はタブ専用sessionStorageとデモ専用利用者IDの保存へ分け、リセットで本番のログイン/記録/設定を消さない。
- 端末通知の許可要求・Service Worker登録・購読復元/解除を行わない。デモ設定では閉じた後の通知欄を出さない。
