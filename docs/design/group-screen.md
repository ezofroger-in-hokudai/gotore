# グループ画面の設計

2026-09-26の検討資料。現段階では5案の比較中で、画面案は未採用。実装済みの共有・権限・履歴集計を変えず、グループホームの構成と参加・招待の見せ方を決める。

## 今回確定した共通条件

- 下部ナビの「グループ」は、選択中グループの有無にかかわらずグループホームへ着地する。個別詳細はホーム内でグループを選んで開く。
- グループホームから、所属グループの確認、作成、参加、表示順の変更へ進める。
- 表示順はホームのカードとグループ切替に共用する現在の本人・ブラウザ単位の順序を維持する。並べ替えはドラッグだけにせず上下操作とキーボードでも行える。
- 詳細ではグループ単位の総負荷、セット数、活動人数、履歴を確認できる。カレンダー・グラフ・記録一覧は個人履歴と共通の部品・集計規則を使う。
- 既存の黒48pxヘッダー、選択トラック、記録カード、スタンプ、フローティングSTART、下部ナビ、色と余白を再利用する。
- 現行の参加処理は12桁招待コードを確認してグループ名・人数を表示し、参加操作時に再検証する。未採用のリンクやQRを、実装済みの機能として案内しない。

## 比較中の5案

| 案 | グループホームの主役 | 特徴 |
| --- | --- | --- |
| A 一覧＋詳細 | 所属グループ一覧 | 今日の数値を比較してから個別詳細を開く基本案。グループ数が増えても探しやすい。 |
| B スワイプ | 横スワイプのグループカード | 現在のホーム操作を最も強く引き継ぐ。選択グループの最新記録を近くに置く。 |
| C 履歴中心 | カレンダーと積み上がり | グループ単位の履歴を最初から確認しやすい。切替と分析が主目的の場合に向く。 |
| D メンバー中心 | LIVE・今日活動した人 | 誰が取り組んでいるかを先に見せる。仲間からグループへ入る。 |
| E 2列ボード | 複数グループの数値比較 | 一画面の情報量を増やした案。長い名称、文字拡大、多数グループ時の確認が必要。 |

すべての案で、プレビュー上部から「ホーム」「詳細・履歴」「設定・順番」「作成・参加」を切り替えられる。

## 次に選ぶ項目

- A〜Eのうちグループホームに採用する構成。
- 参加の主入口を、招待リンク、QR、12桁コードのどれにするか。リンク・QRを採用する場合も、同じ招待コードを運ぶだけにして参加前確認と再検証を維持する案を基準とする。
- グループホームに全体集計を置くか、各グループの当日値だけにするか。
- 詳細の初期表示を最新記録・カレンダー・前回選択のどれにするか。
- グループ設定と全グループの表示順変更を同じ画面に置くか、別のシートに分けるか。
