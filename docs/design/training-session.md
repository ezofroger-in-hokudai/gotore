# トレーニング中の画面設計

トレーニング開始後の種目選択、本人の記録入力、終了について、ユーザーとの検討で確定した判断をまとめる。2026-09-28の追加指定により、仲間の当日記録はホームで確認し、記録画面には表示しない。この文書を、次のプレビュー作成と実装の参照元にする。

共通の色・余白・操作領域・文字量の基準は [デザインルール](../design-system.md) に従う。ここに書く個別画面の判断は、その基準をこの導線へ具体化したものとして優先する。

## この導線で守る共通ルール

- 目的は「開始する → 種目を選ぶ → セットを記録する → その日のトレーニングを終える」を迷わず進めること。説明を足して理解させず、配置・短い文言・図で分かるようにする。
- 数値、種目名、保存済みセット、次に行う操作を主役にする。同期済み、共有先、保存しましたなど、通常時に内容を押し下げたり画面を揺らしたりする状態文は置かない。
- 白・薄いグレーと細い区切り線を基調に、赤は選択中・保存などの主操作・BESTだけに使う。大きい角丸カード、強い影、枠で囲んだ説明文、冗長な見出しは増やさない。
- 一覧もセットも横に詰め込まない。今日のメニュー、今回・前回のセットは、読み進められる縦の行で揃える。
- 読み込みによって既に操作できる場所を止めない。固定サイズのプレースホルダーだけを使い、取得完了で行の位置や画面の高さを大きく変えない。
- 種目選択の変更では、下記の記録入力・終了確認・終了後画面を旧UIへ戻したり、配置や文言を独断で変えたりしない。

## 記録入力（確定・変更しない範囲）

### 全体の配置と操作

- 一つの種目の記録を主画面にし、今回と前回のセットは同じ列の中で対になるように表示する。前回の記録は常に全セットを参照できるようにし、今回だけが離れたり、前回の有無で今回の操作位置が大きくずれたりしない。
- 保存済みセットは行全体を押して同じ場所で編集する。別画面・モーダルへ飛ばさない。編集中のセットをもう一度押すと編集を解除し、最新セットを押すと新しいセットの入力状態へ戻る。
- 新しいセットは入力フォームの`セットを追加`で保存・追加する。最後のセットの下に重複する`＋`入口は置かない。
- 次のセット入力は画面最下部に固定する。初期表示で上に浮かせず、セットを増やしても画面下からすぐ入力できるようにする。必要なときだけ入力フォームをしまえる。
- 保存後に自動スクロールしない。通常の保存成功トースト、`同期中`、件数表示なども出さない。端末に保存したセットの一時的な送信失敗は画面に出さず自動再送する。端末保存失敗と、操作が必要な競合だけは入力を保ったまま表示する。
- `次の種目へ`は端末保存済みセットの送信完了を待たない。別種目を選ぶ際に入力中の数値を捨てる場合だけ、その対象が伝わる文言で確認する。終了確認でもセットに追加していない数値と追加済みセットを区別する。
- 中央に開く終了確認は外側をタップすると閉じる。終了確認で処理中なら既存の閉鎖制限を守る。種目追加は未保存のフォーム入力が失われないよう、背景タップでは閉じず明示的な「閉じる」を使う。下シートの共通操作は[デザインルール](../design-system.md#下から開くシートの閉じ方206)に従う。

### 数値とコピー

- 重量と回数は矢印だけの増減操作を使い、両方とも一回で `+5` / `-5` 相当を動かす。数値入力の見た目・大きさは保ち、矢印だけを少し押しやすくする。数値欄から上下の矢印までの間隔は同じにし、矢印の上下方向と増減方向を逆にしない。
- `重量 kg` と `回数 回` の見出し・単位は入力を開く操作にしない。数値を直接編集したいときだけ、中央の数値欄を押す。
- ルーラーの前後の数値を常時出さない。セット一覧の縦幅を圧迫するならルーラーを優先しない。
- 入力ドックは、数値・矢印の大きさを縮めずに、重量・回数の単位ラベルを`SET`見出しと同じ行かつ各入力欄の真上へ置いて上側の余白を詰める。推定1RMは二つの上矢印の中央に重ね、独立した行を作らない。下部は横幅を維持した`次の種目へ`と`セットを追加`だけを置き、セット一覧下の`＋`や`SET nを記録`の補助文は出さない。編集時も見出しは`SET n`だけとし、色は今回の入力欄だけで示す。
- 種目選択の行は左寄せとする。前回の`何日前`表示や右端の矢印の有無で、種目名の上下位置を動かさない。種目名だけを行の縦中央に固定し、前回表示はその直下に置く。
- 入力中の `前回をコピー` は、前回の対応セットの重量・回数をその場で入力欄へ入れる操作である。コピーしただけで保存・次セット追加・数値編集画面への遷移をしない。
- 対応する前回セットがない場合も、コピー操作で入力状態を失わない。次のセットを追加する必要がある場合は、まず今回側にその新しいセットを作り、その入力欄へ値を入れる。
- 推定1RMは保存状態に関係なく、重量・回数から毎回計算してセットの値の横に表示する。保存完了を待って出すものではない。

### メモと削除

- `今日のメモ` は入力フォームの直前に、`今日のメモ：［本文］`の一行で置く。今日この種目で残したい短いメモという位置づけにし、枠やカードで強調しない。タップでそのまま入力し、Enter または入力欄から離れた時点で保存する。保存・閉じるのボタンは置かず、編集時も文字を大きくしない。長文は一行のまま横スクロールし、フォームを下へ押し出さない。
- 種目メモも`種目メモ：［本文］`の一行で、今日のメモと同じ保存操作・文字サイズにする。本文の背景・囲み枠・大きい角丸は使わない。通信失敗・競合・端末下書きの保護は維持する。
- メモ取得中は同じ高さに「メモ」を表示し、端末に下書きがあればその本文を先に表示する。取得が確定するまで編集は無効にし、読み上げでは「準備中」と伝える。通常の「読み込み中」文言は表示せず、取得失敗時は既存の再試行操作を残す。種目メモと今日のメモに共通の扱いとする。[取得中の修正前](../images/issue-232/before-390.png) / [採用した修正後](../images/issue-232/after-390.png)（390px、合成データ）。
- 削除は白黒のゴミ箱ピクトグラムを使い、ボタンのような大きい面にしない。今回セットの右側で位置を固定し、前回記録の文字数・有無で動かない。

### 終了

- トレーニング開始後の画面は、黒地の左に `E-GOTORE`、右端に `トレーニング終了` を置く共通ヘッダーを残す。`種目を選択` など画面名は表示しない。入力中の種目名は黒ヘッダーの直下に置く。横断的な基準は[デザインシステム](../design-system.md#共通ヘッダー)に従う。
- 共通ヘッダーは端末の上端から始まり、ホームと同じ48pxへ固定する。ロゴもホームと同じ22pxとし、320pxを含む各幅で画面の左右端へ過不足なく合わせる。種目選択・記録入力の切替や画面スクロールで上余白、位置、高さを変えない。
- 画面上の終了入口は `トレーニング終了`、終了確認の確定は赤い `終了する` とする。確認文は `今回のトレーニングを終了しますか？` とし、同じ日の他セッションは終了対象に含めない。
- 種目選択と記録入力の終了入口は、同じ右端・同じ高さ・同じ赤い一行ボタンにする。角丸は両方とも8pxとし、片方だけを角丸なし、薄い文字、別の文字サイズにしない。
- 終了確認は中央に開き、今回の総負荷・セット数・種目数と直近7暦日の日別総負荷を示す。`トレーニングに戻る` と赤い一行の `終了する` を置き、同日内訳や前日比の説明文は置かない。入力中の未追加値がある場合だけ短い注意文を出す。
- `終了する`後は端末への保存を確定して結果画面へ進み、通信完了を待つ文言を出さない。サーバー確定前の結果では`保存済み`・スタンプ・履歴導線を表示しない。確定後に表示する。通常の一時的な送信失敗は画面に出さず再送する。競合時だけ端末に残る内容を確認できるようにする。
- 次回のトレーニング開始は前回終了のサーバー確定まで待つ。単一進行中セッションの制約を守り、待機中は開始操作を無効にする。未保存という警告は出さない。

## 画面の順番

1. 黒い共通ヘッダーの左に `E-GOTORE`、右側に記録入力画面と同じ赤い `トレーニング終了` を置く。画面名は置かない。
2. 種目選択画面に仲間の当日記録・グループ絞り込み・記録詳細への入口は置かない。仲間のタイムラインはホームで確認し、記録画面は本人の入力へ集中させる。記録の共有範囲は変えず、開始時点の全所属グループへ共有する。
3. `今日のトレーニング` はヘッダーの下に置く。0セットでは同じ高さの非操作の「0セット」行を表示し、空の展開操作を出さない。最初のセットができたら初期状態で閉じた展開行に切り替え、`2種目　5セット　3,240kg` のように種目数・セット数・総負荷を一行で表示する。見出しの左に本文より小さい `▶` を置き、押して開くと同じ位置・同じ大きさの `▼` に切り替える。右端には開閉記号を置かない。展開後は全種目・全セットを縦に表示し、セットを横一列には置かない。
   - 0セットの実画面比較: [修正前](../images/issue-229/before-390.png) / [採用した修正後](../images/issue-229/after-390.png)（390px、合成データ）。
4. 部位は8分類を横一列の8等分で置き、横スクロールさせない。ボタンの高さ・文字・角丸はホームのグループ選択と揃え、外周にも4pxの余白を取って端の項目だけが窮屈に見えないようにする。選択は白い面と通常文字、ごく薄い影で示し、下線は使わない。複数選択は和集合で絞り込む。チェックボックス・選択説明・検索欄は置かない。
5. 候補は主部位が一致する種目だけを表示し、よく使う種目を先頭に並べる。各行の補助情報は前回実施からの日数だけとし、10日以上は `10日以上前` と表示する。
6. 最後の入口は `＋ 種目を追加`。部位が1つだけ選ばれているときだけ追加フォームの主部位に初期値を入れる。複数または未選択なら未選択で開き、追加前に利用者が主部位を選ぶ。記録中の追加シートはシート見出しの `種目を追加` だけを表示し、フォーム内には同じ見出しを繰り返さない。

`今日のトレーニング` の総負荷は、画面がすでに持つ今日のセットからその場で計算する。通信待ちにしない。

## 種目一覧（作り直しまでの方針）

- 種目の追加・分類変更・削除を行う一覧は設定からだけ開く画面として、改めてプレビューから設計する。記録中の種目選択には候補を選ぶ操作だけを置き、管理用の一覧・編集フォームを混ぜない。
- 現行の記録中シートを廃止するタイミングは、設定用一覧の採用プレビューと一緒に決める。候補選択、保存済み記録、種目名のデータ形式は維持する。

## 速度と読み込み

- 画面全体を止めるローディング表示や説明文は置かない。部位選択と種目の選択を最優先で操作できるようにする。
- 前回の日数だけは、同じ大きさを保つ控えめなプレースホルダーを許可する。取得完了時に画面の高さ・並びを変えない。
- 種目選択画面から当日記録の集約APIと共有記録詳細APIを呼ばない。

### 実装済みの取得順

1. 開始直後は、すでに取得済みの種目候補を主部位でブラウザ内だけで絞り込む。仲間の通信を待たない。
2. `今日のトレーニング` は画面が保持する本人の保存済みセットだけから計算し、通信を追加しない。
3. `＋ 種目を追加` は、部位が一つだけ選ばれている場合にその主部位を追加フォームへ初期値として渡す。設定用の種目一覧を経由せず、追加フォームを直接開き、追加後は種目選択へ戻る。

## 実装前に決めること

- 全所属グループをまたぐ「今日の記録」の集約API、重複記録の扱い。
- 前回記録がない種目の補助表示。

## 採用プレビューと実装照合

### 終了確認の採用案（実装済み）

2026-09-29に、総負荷を主役にするB案から中央確認B2を選び、問いかけは「今回のトレーニングを終了しますか？」に決定した。現行モデルは同じ日に複数セッションを持て、日付をまたいでも1セッションのままなので、「今日の」では終了対象が曖昧になる。中央配置は以前の下シートの決定を更新した。

今回の追加済みセットによる総負荷・セット数・種目数を上部へ置き、セッションの記録日を終点とする連続7暦日を日別バーで示す。同じ日に複数回トレーニングした場合は合算して1本にするが、今回のセッションを二重計上しない。記録のない日は低い線、保存済み0kg記録は細い棒で区別する。棒を押すと日別合計を確認できる。同日のセッション別内訳や前の活動日との増減文は表示しない。過去記録は非同期取得し、未取得・取得失敗時も7本の位置を保って終了操作を止めない。終了中は二重送信と閉鎖を防ぐ。固定見本は[7日バーの採用プレビュー](../../frontend/public/previews/training-finish-day-bars-adopted.html)とする。
