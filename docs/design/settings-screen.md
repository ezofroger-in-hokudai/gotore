# 設定画面の設計

共通の色・余白・操作領域は[デザインルール](../design-system.md)に従う。この資料は設定画面固有の採用判断を記録する。

## ログアウト

- サポート項目の末尾に置き、文字色を危険操作と同じ赤にする。
- 行を押しただけではログアウトせず、`ログアウト` 見出しの確認シートを開く。
- 確認シートには短い確認文と `キャンセル`、赤い `ログアウト` を置く。
- `キャンセル` と `ログアウト` は同じ8pxの角丸・同じ高さにし、片方だけ形を変えない。
- `キャンセル` は設定画面へ戻し、確定した場合だけローカルセッションを破棄する。
- 処理中は確認シートを閉じたり重複実行したりできないようにする。失敗時はログイン状態を維持し、既存のエラー表示で再試行できるようにする。

## プロフィールの取得と編集（#278）

- 設定一覧、表示名編集、画像編集は、ログイン中のユーザーの同じ取得結果を使う。直後の画面往復・編集を開くだけでは追加取得しない。
- 名前・画像はWorkspace内のメモリだけに保持する。ログアウト・ユーザー切替で破棄し、本人記録の端末スナップショットへ画像を加えない。
- 初回は必要な取得と失敗時の再試行を維持。前回の取得開始から60秒以上経過した再訪は、表示済みデータを保持して背景で再確認する。設定を見ていない間の定期取得は行わない。
- 保存・削除の成功結果を一覧へ即反映し、取り直しが終わるまで表示を待たせない。古い背景応答で新しい保存値を戻さない。Authだけ成功した名前変更は、現行の共有同期の再試行を維持する。
- 設定フォーム・目安箱の下書きの寿命と閉じ方は従来どおり。取得結果の保持によって未送信の入力を永続化しない。

## 触覚設定と種目フォーム（#275・#272）

- 触覚フィードバックは設定一覧のスイッチで直接オン/オフする。専用シートは開かず、一覧に現在値と、セット保存時の振動・対応端末/ブラウザで利用可能という短い説明を置く。端末への保存とユーザー別の設定キーを維持する。
- 種目追加と部位編集のキャンセルは、保存/追加の下に同じ `secondary full` ボタンを置く。文言・角丸・枠・文字・高さを揃え、保存対象と送信中の取消制限を維持する。
- 2026-10-01の継続依頼により採用。その他の設定行・初回ガイドは現在の採用案を使う。変更前後は `docs/images/remaining-fixes/README.md` に記録する。
