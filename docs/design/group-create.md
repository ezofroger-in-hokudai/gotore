# グループ作成画面の設計

2026-09-27の検討資料。グループ画面の採用案と同じヘッダー、管理ボタン、グループカードを使い、グループ名の入力から招待までを設計する。

## 確定している条件

- 入力項目はグループ名だけとする。前後空白を除いた1〜40文字という現行API制約を維持する。
- グループ作成者をオーナー兼最初のメンバーとする既存仕様を維持する。
- 作成後は同じ高さのシート内を招待画面へ切り替え、作成したグループ名、QR、リンク共有を表示する。グループカードは再掲しない。
- 招待はグループ名とQRを黒い招待パスにまとめ、QR中央に既存のバーベルを上げるウォンバットを載せる。リンク共有が使えない端末では同じボタンからコピーし、それも不可なら手動選択できるリンクを示す。
- 作成・招待の操作部品はグループ画面で採用した白ピル、赤い線画アイコンを使う。作成確定はSTARTと混同しない黒い確定ボタンとする。
- 作成中・送信中などの通常進行表示は追加しない。二重送信を防ぎつつ、完了後の画面へ進める。

| C カード入力 | 黒いグループカード内へ直接入力 | カードとの関係は明快だが、通常フォームと操作が異なる。 |

## 採用案: グループ一覧上のボトムシート

2026-09-27、Aの最小フォームを独立ページではなくグループ一覧上のボトムシートとして採用した。

- 一覧上部の共通管理ボタン「作成」からシートを開く。背景のグループ一覧は残し、シート表示中は操作不可にする。
- シートの入力項目はグループ名と文字数だけ。作成確定ボタンがソフトキーボードで隠れない高さとスクロールを確保する。
- ブラウザ・端末の戻る操作はシートを閉じ、グループ一覧からは離れない。
- 作成が完了したら、シートの高さとタイトル位置を動かさず、同じシート内を `メンバーを招待` へ切り替える。作成したグループ名、初期表示したQR、`リンクを共有` だけを置き、通常の送信中表示や完了報告は置かない。
- シートを閉じると、作成したグループカードを一覧の先頭へ反映する。
- 作成前後で同じ高さを維持し、小さい画面やソフトキーボード表示中に収まらない場合だけシート内をスクロールする。

### 招待リンクの使い方

- QRと共有リンクは同じ招待トークンを使う。
- 招待は参加人数では無効にならず、同じリンク・QRを複数人が使える。新しい招待を発行しても以前のリンクは期限まで有効とする。
- 有効期限は発行から7日間とする。期限切れの場合は、メンバーが新しい招待を発行する。
- 作成後のシートと既存グループの招待画面で、上記ルールと表示を共通化する。
- 画面プレビューではQRをサンプルとして表示し、本物の招待先として使えないことを明確にする。
