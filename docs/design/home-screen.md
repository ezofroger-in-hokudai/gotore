# ホーム画面の設計

ホームで「仲間と一緒にトレーニングしている感覚」と記録開始への近さを両立するための、検討中の判断を置く。横断的な色・文字・操作領域は[デザインルール](../design-system.md)、記録中のアイコン・仲間表示の採用済み判断は[トレーニング中の画面設計](training-session.md)を参照する。

## 採用プレビュー

[ホーム採用形](../../frontend/public/previews/home-adopted.html)を実装・画面確認の固定参照にする。黒い共通ヘッダー、4列要約、近接したグループカード、全セットを開いた記録カード、浮遊する `START / RESUME` を一画面に統合する。

全所属グループを混ぜたタイムラインを初期表示にし、個別グループへ絞り込む操作は検討中。[「すべて」の選択方法4案](../../frontend/public/previews/home-all-groups-options.html)では、採用済みホームを変えずに、A 数値ヘッダー、B 固定ピル、C 半幅パネル、D 右上メニューを比較する。全案で個別グループカードの横スワイプと長押し並べ替えを残し、`すべて` 自体は並べ替え対象にしない。

## 過去の比較プレビュー

[ホーム上部の3案](../../frontend/public/previews/home-options.html)を、実アプリとは独立して比較する。数値・表示名は架空で、保存・通信・共有範囲の変更は含まない。

ユーザーから「グループカードを主役にしない」「最新順のトレーニングを見ながらスタンプを押せるタイムライン」「グループで絞り込む」という追加方向を受け、[タイムライン中心の4案](../../frontend/public/previews/home-timeline-options.html)を追加した。現在はこの4案を優先して比較する。いずれもフィルター・スタンプを操作できる静的プレビューであり、実送信は行わない。

さらに、今日の活動型を起点に、アイコンなし・トレーニング単位の4案を[今日の活動の4案](../../frontend/public/previews/home-activity-options.html)として比較する。

ユーザーが基本の時系列を選択。次の比較用として、上部にLIVE・今日の人数・セット数・総負荷を置き、LIVE中の仲間をタイムライン外で強調し、各トレーニングの種目・重量・回数・セットを展開した[時系列の詳細案](../../frontend/public/previews/home-activity-timeline-v2.html)を作成した。この時点では実装採用前の調整案とする。

共通の記録カードを変えず、ホームでの配置だけを比較する[3案](../../frontend/public/previews/home-placement-options.html)を追加した。

次の調整では、全体の4列要約を固定し、個別グループのスワイプ式カードとの距離と強弱だけを比較する。[調整案1](../../frontend/public/previews/home-refinement-v1.html)。

## 採用: 4列要約とグループカードは近接

2026-09-25、ユーザーが調整案1のA「近接」を選択した。ホーム上部は全体の `LIVE / 今日 / セット / 総負荷` の4列要約を置き、その直下にスワイプで切り替える個別グループカードを置く。今後はこの距離・順序を戻さず、カード内の情報配置など未決定の箇所だけを比較する。

## 採用: グループカードは基本形

2026-09-25、調整案2のA「基本」を選択。カード内には分類ラベル `GROUP` を置かない。グループ名、LIVE状態、セット数、総負荷、詳細への矢印だけを表示する。

実装時のカード面は採用プレビューと同じ `#202127` の濃色とする。LIVEの赤い点は真円で、カード内では `n人がトレーニング中` をグループ名の上に置く。これはホーム上の入口だけの決定であり、グループ画面そのものの構成は未決定のため、ホーム実装から新しく作らない。

黒いLIVE用カードは不要というフィードバックを受け、現行のグループカードを残す量だけを比較する[現行カードを生かす4案](../../frontend/public/previews/home-current-card-options.html)を追加した。

| 案 | 上部の構成 | 向く点 | 検討点 |
| --- | --- | --- | --- |
| A 仲間ドック | グループ名、LIVE人数、アバター、今日の人数・セット数を濃い面に集約 | 仲間の気配を最初に伝えやすい | 濃い面の情報量と高さ |
| B アイコン入口 | グループ、LIVE、前回を同じアイコン付き入口として横並び | トレーニング画面・履歴にも入口部品を再利用しやすい | グループの一体感が弱くならないか |
| C チームボード | グループ名、LIVE/TODAY/SETS、今日の仲間を区切り線で並べる | 硬派で情報を比較しやすい | 数値が多すぎないか |

| 案 | タイムライン上部の構成 | 向く点 | 検討点 |
| --- | --- | --- | --- |
| A タイムライン | グループ/LIVEのチップ → 最新順フィード | 一番早く記録を見て反応できる | 仲間の存在を補う量 |
| B 仲間レール | 最近・LIVEの仲間アイコン列 → フィード | Instagramのように人から入れる | 人数が多い場合の表示 |
| C 種目選択型 | グループ/LIVEと部位の選択行 → フィード | 種目選択と選択状態を共通化できる | 部位絞り込みを初期から提供するか |
| D 今日の活動 | LIVE/TODAY/SETSの細い要約 → フィード | グループカードなしで全体の熱量が分かる | 数値要約を常設する必要性 |

## 守ること

- ヘッダーは高さ48pxの黒地、左に `E-GOTORE` だけを置く。`ホーム`などの画面名や右側操作は置かない。
- ヘッダー直下は `LIVE / 今日 / セット / 総負荷` の4列とし、全所属グループで同じトレーニングを重複集計しない。
- 個別グループカードは4列要約へ近接させ、グループ名、赤いLIVE状態、セット数、総負荷、詳細矢印を表示する。`GROUP` と `今日` のラベルは置かない。横スワイプと長押し並べ替えを維持する。
- タイムラインは保存されたトレーニング単位の時系列とし、種目ごとのカードへ分割しない。種目と全セット、各セットの推定1RM、BEST、6種類のスタンプを既存の共通記録カードで表示する。
- タイムラインの記録は白い小型カードにまとめ、日付と時刻をカード最上部、続けて記録者、総負荷・セット数、6種類のスタンプ、種目と全セットを置く。総負荷などの数値だけを過度に大きくしない。LIVEの記録でも左側へ赤線を追加しない。
- スタンプ操作はトレーニング画面の仲間の記録と同じ共通部品・同じ順序・同じ選択表示を使う。6種類を最初から表示し、日本語の意味説明は付けない。
- LIVE、人数、セット数は保存済みの既存集計だけを示す。新しい公開範囲・通知・集計規則をプレビューから追加しない。
- 記録開始は既存サイズのフローティング `START / RESUME` を維持する。主要4画面に重ね、長押しで移動、左右端へ吸着し、ユーザー・端末ごとに位置を保存する。記録画面、シート、入力フォーカス中は隠す。
- グループ詳細、スタンプ受信一覧、履歴への遷移先と既存の共有権限は維持する。全グループ横断の最新順フィードは現行の選択グループ別取得と異なるため、採用時にAPI・キャッシュ・共有解除時の扱いを別途設計する。
## 保留

- 全グループ混在表示へ戻る操作。4案を比較中で、初期値は `すべて`、個別カードは長押し並べ替え可能、同一記録は重複表示しないところまでを共通条件とする。
- グループなし、通信失敗、記録が50件を超える場合のページング表現。
- グループ画面の情報構成と操作。ホームのグループカードから推測して新設・変更しない。
- トレーニング入力フォームの大きさと配置。ホーム実装とは分離して後続Issueで扱う。
