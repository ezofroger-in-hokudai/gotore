# ホーム画面の設計

ホームで「仲間と一緒にトレーニングしている感覚」と記録開始への近さを両立するための、検討中の判断を置く。横断的な色・文字・操作領域は[デザインルール](../design-system.md)、記録中のアイコン・仲間表示の採用済み判断は[トレーニング中の画面設計](training-session.md)を参照する。

## 採用プレビュー

[ホーム採用形](../../frontend/public/previews/home-adopted.html)を実装・画面確認の固定参照にする。黒い共通ヘッダー、4列要約、近接したグループカード、全セットを開いた記録カード、浮遊する `START / RESUME` を一画面に統合する。

全所属グループを混ぜたタイムラインを初期表示にし、個別グループへ絞り込む操作は検討中。[「すべて」の選択方法4案](../../frontend/public/previews/home-all-groups-options.html)では、採用済みホームを変えずに、A 数値ヘッダー、B 固定ピル、C 半幅パネル、D 右上メニューを比較する。全案で個別グループカードの横スワイプと長押し並べ替えを残し、`すべて` 自体は並べ替え対象にしない。

2026-09-26、上記A〜Cは不採用とし、グループカードとタイムラインの表示範囲を別操作にする方向を採用した。グループカードは状況確認、長押し並べ替え、グループ詳細への入口だけを担当し、カードの選択状態でタイムラインを絞り込まない。新しい[タイムライン直前の絞り込み4案](../../frontend/public/previews/home-feed-filter-options.html)で、A 下線タブ、B 小型チップ、C 右上選択、D 選択バーを比較する。

同日、A 下線タブを採用した。[タイムライン絞り込み採用形](../../frontend/public/previews/home-feed-filter-adopted.html)を固定参照にする。初期値は `すべて` とし、見出し直下の横スクロール可能な選択列で個別グループへ絞り込む。グループカードの操作とタイムラインの絞り込みは連動させない。その後の横断指定により、選択列の見た目だけはグループ分析の `カレンダー / 最新記録 / グラフ` と同じ、薄いトラック上へ選択中の白い面を置く形へ更新した。高さと表示順、絞り込みの責務は変えない。

種目数・セット数が多い記録の確認には、[多種目・多セット確認](../../frontend/public/previews/home-feed-many-sets.html)を使う。1回のトレーニングは種目ごとに別カードへ分割せず、同じ記録カード内へ全種目・全セットを縦に続け、ページ全体をスクロールして読む。確認用の先頭記録は5種目・22セットとする。浮遊する `START / RESUME` と下部ナビゲーションは、記録が長くても従来どおり画面上に維持する。

上記の全展開が長くなるため、[長い記録カードの4案](../../frontend/public/previews/home-long-record-options.html)で、同じ5種目・22セットを使って初期表示量を比較した。トレーニング単位の1カード、日付・記録者・要約・スタンプ、全セットへ到達できることは全案で共通とした。

| 案 | 初期表示 | 全セットの見方 |
| --- | --- | --- |
| A 全展開 | 現在案どおり全種目・全セット | そのまま縦スクロール |
| B 固定＋フェード | カードを一定高で切り、下端をフェード | 文字のないフェード部分を押して同じカードを展開 |
| C 種目ごと | 種目名・セット数と、先頭種目のセット | 種目行を押して個別に開閉 |
| D 概要＋詳細 | 種目名・セット数だけの短いカード | `詳細を見る`で下から全記録を開く |

2026-09-26、B 固定＋フェードを採用した。ホームの小型記録カードだけ、種目・セット部分を初期状態で最大352pxに収め、内容が続く場合はカードの左右端から下端まで104pxの薄いチャコールフェードを重ねる。下端は16%程度の暗さに留め、続きとタップ領域を文字なしで示す。`全て表示`などの可視ラベルや開閉アイコンは置かない。フェードを含む記録カード内の余白・日付・記録者・要約・種目・セットを押すと全展開し、もう一度押すと固定高へ戻す。スタンプなど別の操作ボタンを押した場合はカードを開閉しない。タッチ時のブラウザ標準の青いハイライトはこの開閉カードだけ無効にし、キーボードのフォーカス表示は残す。スクリーンリーダーには状態に応じて記録者名を含む `全セットを表示 / 記録を小さく表示` の操作名を提供する。履歴・スタンプ詳細・トレーニング中など、ホーム以外の通常サイズの記録カードは従来どおり全展開を維持する。

## 過去の比較プレビュー

[ホーム上部の3案](../../frontend/public/previews/home-options.html)を、実アプリとは独立して比較する。数値・表示名は架空で、保存・通信・共有範囲の変更は含まない。

ユーザーから「グループカードを主役にしない」「最新順のトレーニングを見ながらスタンプを押せるタイムライン」「グループで絞り込む」という追加方向を受け、[タイムライン中心の4案](../../frontend/public/previews/home-timeline-options.html)を追加した。現在はこの4案を優先して比較する。いずれもフィルター・スタンプを操作できる静的プレビューであり、実送信は行わない。

さらに、今日の活動型を起点に、アイコンなし・トレーニング単位の4案を[今日の活動の4案](../../frontend/public/previews/home-activity-options.html)として比較する。

ユーザーが基本の時系列を選択。次の比較用として、上部にLIVE・今日の人数・セット数・総負荷を置き、LIVE中の仲間をタイムライン外で強調し、各トレーニングの種目・重量・回数・セットを展開した[時系列の詳細案](../../frontend/public/previews/home-activity-timeline-v2.html)を作成した。この時点では実装採用前の調整案とする。

共通の記録カードを変えず、ホームでの配置だけを比較する[3案](../../frontend/public/previews/home-placement-options.html)を追加した。

次の調整では、全体の4列要約を固定し、個別グループのスワイプ式カードとの距離と強弱だけを比較する。[調整案1](../../frontend/public/previews/home-refinement-v1.html)。

## 採用: 4列要約とグループカードは近接

2026-09-25、ユーザーが調整案1のA「近接」を選択した。ホーム上部は全体の `LIVE / 今日 / セット / 総負荷` の4列要約を置き、その直下にスワイプで切り替える個別グループカードを置く。今後はこの距離・順序を戻さず、カード内の情報配置など未決定の箇所だけを比較する。

## 採用: グループカードは基本形

2026-09-25、調整案2のA「基本」を選択。カード内には分類ラベル `GROUP` を置かない。グループ名、LIVE状態、セット数、総負荷、詳細への矢印だけを表示する。

実装時のカード面は採用プレビューと同じ `#202127` の濃色とする。LIVEの赤い点は真円で、カード内では `n人がトレーニング中` をグループ名の上に置く。これはホーム上の入口だけの決定であり、グループ画面そのものの構成は未決定のため、ホーム実装から新しく作らない。

黒いLIVE用カードは不要というフィードバックを受け、現行のグループカードを残す量だけを比較する[現行カードを生かす4案](../../frontend/public/previews/home-current-card-options.html)を追加した。

| 案 | 上部の構成 | 向く点 | 検討点 |
| --- | --- | --- | --- |
| A 仲間ドック | グループ名、LIVE人数、アバター、今日の人数・セット数を濃い面に集約 | 仲間の気配を最初に伝えやすい | 濃い面の情報量と高さ |
| B アイコン入口 | グループ、LIVE、前回を同じアイコン付き入口として横並び | トレーニング画面・履歴にも入口部品を再利用しやすい | グループの一体感が弱くならないか |
| C チームボード | グループ名、LIVE/TODAY/SETS、今日の仲間を区切り線で並べる | 硬派で情報を比較しやすい | 数値が多すぎないか |

| 案 | タイムライン上部の構成 | 向く点 | 検討点 |
| --- | --- | --- | --- |
| A タイムライン | グループ/LIVEのチップ → 最新順フィード | 一番早く記録を見て反応できる | 仲間の存在を補う量 |
| B 仲間レール | 最近・LIVEの仲間アイコン列 → フィード | Instagramのように人から入れる | 人数が多い場合の表示 |

## 守ること

- ヘッダーは高さ48pxの黒地、左に `E-GOTORE` だけを置く。`ホーム`などの画面名や右側操作は置かない。
- ヘッダー直下に短く `TODAY` と置き、全所属グループの今日の活動を4列表示する。同じトレーニングを重複集計しない。1列目だけ `LIVE` を表示し、残りは `7人 / 31セット / 28,400kg` のように単位で意味を示す。`今日 / セット / 総負荷` の説明ラベルと `t` 表記は使わない。2列目の人数は今日トレーニングした重複なしの人数である。
- 個別グループカードは4列要約へ近接させ、グループ名、赤いLIVE状態、今日トレーニング中またはトレーニング済みの人のアイコン、今日の人数、セット数、kg単位の総負荷、詳細矢印を表示する。プロフィール画像がなければ既存アバターと同じ名前の先頭文字を使い、LIVE中の人だけ既存の赤い外周と右下点を付ける。グループ自体のアイコンや総所属人数ではない。`GROUP` と `今日` のラベルは置かない。横スワイプと長押し並べ替えを維持する。
- タイムラインの絞り込みは `みんなのトレーニング` 直下の `すべて / 各グループ` の選択列だけで行う。初期表示は全所属グループの記録を重複なしで混ぜた `すべて` とし、日時の新しい順に並べる。グループカードは絞り込みに使わず、状況確認・並べ替え・詳細への入口に限定する。
- `みんなのトレーニング` と選択列は一つの操作領域に見えるよう近接させ、大きい説明用の余白を挟まない。選択列は横スクロールでき、グループ分析タブと同じ選択表現を使う。
- `カードはグループ詳細への入口です` や `新しい順` のように、配置や時系列から分かる補助文は表示しない。
- タイムラインは保存されたトレーニング単位の時系列とし、種目ごとのカードへ分割しない。ホームの長い記録は固定高＋下端フェードで初期表示を抑え、カード内を押すたびに固定高と全展開を切り替える。各セットの推定1RM、BESTを確認できるようにし、6種類のスタンプは記録カードへ表示する。
- タイムラインの記録は白い小型カードにまとめ、日付と時刻をカード最上部、続けて記録者、総負荷・セット数、6種類のスタンプ、種目と全セットを置く。総負荷などの数値だけを過度に大きくしない。LIVEの記録でも左側へ赤線を追加しない。
- スタンプ操作はトレーニング画面の仲間の記録と同じ共通部品・同じ順序・同じ選択表示を使う。6種類を最初から表示し、日本語の意味説明は付けない。
- ホーム下部には `届いたスタンプ` と `前回を振り返る` を置かない。ホームはみんなの頑張りを見る画面に絞り、届いたスタンプは既存のグループ詳細・記録結果、過去の記録は履歴で確認する。
- LIVE、人数、セット数は保存済みの既存集計だけを示す。新しい公開範囲・通知・集計規則をプレビューから追加しない。
- 記録開始は112×52px固定のフローティング `START / RESUME` を維持する。文言の切替時や長押し移動中も横幅を広げず、影だけで移動状態を示す。主要4画面に重ね、長押しで移動、左右端へ吸着し、ユーザー・端末ごとに位置を保存する。記録画面、シート、入力フォーカス中は隠す。
- グループ詳細、スタンプ受信一覧、履歴への遷移先と既存の共有権限は維持する。ホームは今日の全グループ取得結果から表示用タイムラインを組み立て、複数グループへ共有された同じ記録は1件にまとめる。詳細とスタンプは、その記録を取得できた共有先グループを使い、カード移動時に別グループの記録へ差し替えない。
## 保留

- グループなし、通信失敗、記録が50件を超える場合のページング表現。
- グループ画面の情報構成と操作。ホームのグループカードから推測して新設・変更しない。
- トレーニング入力フォームの大きさと配置。ホーム実装とは分離して後続Issueで扱う。
